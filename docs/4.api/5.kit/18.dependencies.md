模块常常依赖某个只有部分项目才需要、或者期望由用户自己安装的包。与其假定这个包一定存在，或者为用户根本不使用的包管理器打印一条安装命令，Nuxt Kit 可以检查某个依赖是否可以被解析到，并主动提出用项目自己的包管理器来安装它。

## `ensureDependencyInstalled`

检查一个或多个依赖是否已安装，并在缺少依赖时提示用户进行安装。

### 用法

```ts twoslash
import { defineNuxtModule, ensureDependencyInstalled } from '@nuxt/kit'

export default defineNuxtModule({
  async setup () {
    if (!await ensureDependencyInstalled('sass')) {
      return
    }
  },
})
```

### 类型

```ts
function ensureDependencyInstalled (names: string, options?: EnsureDependencyInstalledOptions): Promise<boolean>
function ensureDependencyInstalled (names: string[], options?: EnsureDependencyInstalledOptions): Promise<true | string[]>
```

### 参数

**`names`**：要检查（缺失时安装）的一个或多个包名。

**`options`**：

| 属性      | 类型       | 默认值     | 描述                                                                                                                                                            |
| ------------- | ---------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `rootDir`     | `string`   | `nuxt.options.rootDir` | 解析包时所在的目录，也是安装到的目录。                                                                                                     |
| `searchPaths` | `string[]` | `nuxt.options.modulesDir` | 解析包时额外查找的目录。                                                                                                         |
| `from`        | `string`   | `undefined` | 解析包时额外使用的 URL 或路径，例如 `import.meta.url`。当你自己的包把该依赖作为 peer dependency 一并提供时很有用。                       |
| `prompt`      | `boolean`  | `undefined` | 安装前是否进行提示。`true` 总是提示，`false` 从不提示（并且在 StackBlitz 上会自动安装），而不设置该值时，除 StackBlitz 之外都会提示。 |
| `dev`         | `boolean`  | `true`      | 是否将该依赖安装为 dev dependency。                                                                                                     |

### 返回值

传入单个包名时，如果该包可用则返回 `true`，不可用则返回 `false`。传入数组时，如果所有包都可用则返回 `true`，否则返回仍未安装成功的包名数组（可能是因为用户拒绝安装、安装失败，或者没有可交互的终端）。

::note
在 CI 中或没有可交互终端时不会安装任何东西。在这种情况下，缺失的包会作为一条诊断信息上报，其中包含安装命令，同时该函数也会把它们报告为缺失，以便你的模块能够优雅降级。
::

## `getAddDependencyCommand`

获取用户应该运行的、用于向项目添加依赖的命令。它会根据从 `cwd` 检测到的包管理器生成命令，并回退到 `npm`。每当你需要打印一条安装指引时都应该使用它，这样命令就能与项目的包管理器保持一致。

### 用法

```ts twoslash
import { defineNuxtModule, getAddDependencyCommand, useLogger } from '@nuxt/kit'

export default defineNuxtModule({
  async setup (options, nuxt) {
    const logger = useLogger('my-module')
    const command = await getAddDependencyCommand('sass', nuxt.options.rootDir, { dev: true })

    logger.warn(`\`sass\` is required. Run \`${command}\` to install it.`)
  },
})
```

### 类型

```ts
function getAddDependencyCommand (names: string | string[], cwd: string, options?: { dev?: boolean }): Promise<string>
```

### 参数

**`names`**：要安装的一个或多个包名。

**`cwd`**：用于检测包管理器的目录。

**`options.dev`**：该命令是否应把这些包安装为 dev dependencies。
