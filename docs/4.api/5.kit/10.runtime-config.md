## `useRuntimeConfig`

在构建时，可以访问已解析的 Nuxt [运行时配置](/docs/guide/going-further/runtime-config)。

匹配的环境变量会以与运行时相同的方式被应用和转换。在 `runtimeConfig` 中声明的 schema 会被替换为它们的默认值。

::tip
在模块中，请优先使用 `useRuntimeConfig()` 而不是读取 `nuxt.options.runtimeConfig`。`nuxt.options.runtimeConfig` 只包含默认值，不会应用环境变量。
::

### 类型

```ts
function useRuntimeConfig (): Record<string, unknown>
```

## `updateRuntimeConfig`

也可以更新运行时配置。它会与已有的运行时配置合并；如果 Nitro 已经初始化，则会触发一个 HMR 事件来重新加载 Nitro 运行时配置。

### Schema

传给 `updateRuntimeConfig` 的值可以是一个 [schema](/docs/guide/going-further/runtime-config#validating-with-a-schema)，用于设置该值的类型及其默认值：

```ts
import { defineNuxtModule, updateRuntimeConfig } from '@nuxt/kit'
import { z } from 'zod'

export default defineNuxtModule({
  setup () {
    updateRuntimeConfig({
      myModule: z.object({
        apiKey: z.string(),
        retries: z.number().default(3),
      }),
    })
  },
})
```

schema 会立即被替换为其默认值，因此后续的模块从 `nuxt.options.runtimeConfig` 中读到的就是普通值。如果用户已经在相同路径上设置了值，例如其 `nuxt.config` 中的 `runtimeConfig.myModule.apiKey`，该值会被保留并成为这个 schema 的默认值。如果用户在相同路径上自己声明了 schema，那么用户的 schema 优先于模块的 schema。

直接把 schema 赋值给 `nuxt.options.runtimeConfig` 会抛出错误。

::note
在不支持运行时配置 schema 的 Nuxt 版本上，schema 会被替换为其默认值且不会进行校验。没有默认值的必填项会变成空字符串，因此环境变量仍然可以覆盖它。
::

### 类型

```ts
function updateRuntimeConfig (config: Record<string, unknown>): void | Promise<void>
```
