模块是 Nuxt 的构建基石。Kit 提供了一系列工具，帮助你创建和使用模块。你可以使用这些工具来创建自己的模块，或复用已有的模块。例如，你可以使用 `defineNuxtModule` 函数定义一个模块，并使用 `moduleDependencies` 选项指定依赖。

## `defineNuxtModule`

定义一个 Nuxt 模块，自动将默认值与用户提供的选项合并，安装所提供的任何钩子，并调用一个可选的 setup 函数以获得完全的控制。

### 用法

```ts twoslash
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  defaults: {
    enabled: true,
  },
  setup (options) {
    if (options.enabled) {
      console.log('My Nuxt module is enabled!')
    }
  },
})
```

### 类型

```ts twoslash
// @errors: 2391
import type { ModuleDefinition, ModuleOptions, NuxtModule } from '@nuxt/schema'
// ---cut---
export function defineNuxtModule<TOptions extends ModuleOptions> (
  definition?: ModuleDefinition<TOptions, Partial<TOptions>, false> | NuxtModule<TOptions, Partial<TOptions>, false>,
): NuxtModule<TOptions, TOptions, false>

export function defineNuxtModule<TOptions extends ModuleOptions> (): {
  with: <TOptionsDefaults extends Partial<TOptions>> (
    definition: ModuleDefinition<TOptions, TOptionsDefaults, true> | NuxtModule<TOptions, TOptionsDefaults, true>,
  ) => NuxtModule<TOptions, TOptionsDefaults, true>
}
```

### 参数

**definition**：一个模块定义对象或一个模块函数。模块定义对象应包含以下属性：

| 属性              | 类型                                                                                                              | 必填    | 描述                                                                                                                       |
|-------------------|-------------------------------------------------------------------------------------------------------------------|---------|---------------------------------------------------------------------------------------------------------------------------|
| `meta`            | `ModuleMeta`                                                                                                      | `false` | 模块的元数据。它定义了模块名称、版本、config key 和兼容性。                                                                |
| `defaults`        | `T \| ((nuxt: Nuxt) => T)`{lang="ts"}                                                                             | `false` | 模块的默认选项。如果提供的是函数，会以 Nuxt 实例作为第一个参数被调用。                                                    |
| `schema`          | `T`                                                                                                               | `false` | 模块选项的 schema。如果提供，选项会被应用到该 schema。                                                                     |
| `hooks`           | `Partial<NuxtHooks>`{lang="ts"}                                                                                   | `false` | 为模块安装的钩子。如果提供，模块会安装这些钩子。                                                                           |
| `moduleDependencies` | `Record<string, ModuleDependency> \| ((nuxt: Nuxt) => Record<string, ModuleDependency>)`{lang="ts"}         | `false` | 对其他模块的依赖，包含版本约束与配置。可以是一个对象，也可以是一个接收 Nuxt 实例的函数。参见 [示例](/docs/api/kit/modules#指定模块依赖)。 |
| `onInstall`       | `(nuxt: Nuxt) => Awaitable<void>`{lang="ts"}                                                                      | `false` | 模块首次安装时调用的生命周期钩子。需要定义 `meta.name` 和 `meta.version`。                                                |
| `onUpgrade`       | `(nuxt: Nuxt, options: T, previousVersion: string) => Awaitable<void>`{lang="ts"}                                 | `false` | 模块升级到新版本时调用的生命周期钩子。需要定义 `meta.name` 和 `meta.version`。                                           |
| `setup`           | `(this: void, resolvedOptions: T, nuxt: Nuxt) => Awaitable<void \| false \| ModuleSetupInstallResult>`{lang="ts"} | `false` | 模块的 setup 函数。如果提供，模块会调用该函数。                                                                            |

### 示例

#### 使用 `configKey` 使你的模块可配置

定义一个 Nuxt 模块时，你可以设置 `configKey` 来指定用户应在其 `nuxt.config` 中如何配置该模块。

```ts
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  defaults: {
    // 模块选项
    enabled: true,
  },
  setup (options) {
    if (options.enabled) {
      console.log('My Nuxt module is enabled!')
    }
  },
})
```

用户可以在 `nuxt.config` 中对应的 key 下为该模块提供选项。

```ts
export default defineNuxtConfig({
  myModule: {
    enabled: false,
  },
})
```

用户也可以通过将该 config key 设为 `false` 来完全禁用某个模块。这会阻止模块 setup 函数运行，同时仍然为模块选项生成类型。

```ts
export default defineNuxtConfig({
  // 完全禁用该模块
  myModule: false,
})
```

:tip
当你想禁用从 [Nuxt 层](/docs/guide/going-further/layers#从层中禁用模块) 继承来的模块时，这尤其有用。
:

#### 定义模块兼容性要求

如果你在开发 Nuxt 模块，并且使用了仅在特定 Nuxt 版本中受支持的 API，强烈建议包含 `compatibility.nuxt`。

```ts
export default defineNuxtModule({
  meta: {
    name: '@nuxt/icon',
    configKey: 'icon',
    compatibility: {
      // 以 semver 格式表示的所需 nuxt 版本。
      nuxt: '>=3.0.0', // 或使用 '^3.0.0'
    },
  },
  setup () {
    const resolver = createResolver(import.meta.url)
    // 实现
  },
})
```

如果用户尝试在不兼容的 Nuxt 版本上使用你的模块，他们会在控制台收到一条警告。

```terminal
 WARN  Module @nuxt/icon is disabled due to incompatibility issues:
 - [nuxt] Nuxt version ^3.1.0 is required but currently using 3.0.0
```

#### 使用 `.with()` 对解析后的选项进行类型保护

当你需要为解析后/合并后的模块选项提供类型安全时，可以使用 `.with()` 方法。这样 TypeScript 就能正确推断出模块默认值与你 setup 函数最终接收到的解析选项之间的关系。

```ts
import { defineNuxtModule } from '@nuxt/kit'

// 定义你的模块选项接口
interface ModuleOptions {
  apiKey: string
  baseURL: string
  timeout?: number
  retries?: number
}

export default defineNuxtModule<ModuleOptions>().with({
  meta: {
    name: '@nuxtjs/my-api',
    configKey: 'myApi',
  },
  defaults: {
    baseURL: 'https://api.example.com',
    timeout: 5000,
    retries: 3,
  },
  setup (resolvedOptions, nuxt) {
    // resolvedOptions 的类型为：
    // {
    //   apiKey: string          // 必填，无默认值
    //   baseURL: string         // 必填，有默认值
    //   timeout: number         // 可选，有默认值
    //   retries: number         // 可选，有默认值
    // }

    console.log(resolvedOptions.baseURL) // ✅ TypeScript 知道这总是有定义的
    console.log(resolvedOptions.timeout) // ✅ TypeScript 知道这总是有定义的
    console.log(resolvedOptions.retries) // ✅ TypeScript 知道这总是有定义的
  },
})
```

不使用 `.with()` 时，`resolvedOptions` 参数会被类型化为原始的 `ModuleOptions` 接口，即使提供了默认值，`timeout` 和 `retries` 仍可能为 `undefined`。`.with()` 方法让 TypeScript 理解默认值使这些属性在解析后的选项中变为非可选。

#### 使用生命周期钩子处理模块安装与升级

你可以定义在模块首次安装或升级到新版本时运行的生命周期钩子。这些钩子适合用于执行一次性设置任务、数据库迁移或清理操作。

:important
要让生命周期钩子生效，你**必须**在模块定义中同时提供 `meta.name` 和 `meta.version`。这些钩子使用这些值来在项目 `.nuxtrc` 文件中跟踪模块的安装状态。
:

生命周期钩子在主 `setup` 函数之前运行，如果某个钩子抛出错误，错误会被记录但不会停止构建过程。

**`onInstall`** 仅在模块首次加入项目时运行一次。

**`onUpgrade`** 在模块版本升高（使用 semver 比较）时每次都会运行——但每个版本提升只运行一次。

##### 示例

```ts
import { defineNuxtModule } from '@nuxt/kit'
import { isLess } from 'verkit'

export default defineNuxtModule({
  meta: {
    name: 'my-awesome-module',
    version: '1.2.0', // 生命周期钩子所必需
    configKey: 'myAwesomeModule',
  },
  defaults: {
    apiKey: '',
    enabled: true,
  },

  onInstall (nuxt) {
    // 仅在模块首次安装时运行
    console.log('Setting up my-awesome-module for the first time!')

    // 你可能希望：
    // - 创建初始配置文件
    // - 设置数据库 schema
    // - 显示欢迎信息
    // - 执行初始数据迁移
  },

  onUpgrade (nuxt, options, previousVersion) {
    // 当模块升级到新版本时运行
    console.log(`Upgrading my-awesome-module from ${previousVersion} to 1.2.0`)

    // 你可能希望：
    // - 迁移配置文件
    // - 更新数据库 schema
    // - 清理已弃用的文件
    // - 显示升级说明

    if (isLess(previousVersion, '1.1.0')) {
      console.log('⚠️  1.1.0 中的破坏性变更 - 请查阅迁移指南')
    }
  },

  setup (options, nuxt) {
    // 常规 setup 逻辑在每次构建时运行
    if (options.enabled) {
      // 配置模块
    }
  },
})
```

#### 指定模块依赖

你可以使用 `moduleDependencies` 选项来声明对其他模块的依赖。这是一种健壮的方式，可确保正确的初始化顺序、版本兼容性以及配置管理。

`moduleDependencies` 选项可以是一个对象，也可以是一个接收 Nuxt 实例的函数：

##### 示例

```ts
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
  },
  moduleDependencies: {
    '@nuxtjs/tailwindcss': {
      // 指定版本约束（semver 格式）
      version: '>=6.0.0',
      // 覆盖用户设置的配置
      overrides: {
        exposeConfig: true,
      },
      // 设置默认值但尊重用户设置的配置
      defaults: {
        config: {
          darkMode: 'class',
        },
      },
    },
    '@nuxtjs/fontaine': {
      // 可选依赖不会被安装，但确保它们被安装时可以设置选项
      optional: true,
      defaults: {
        fonts: [
          {
            family: 'Roboto',
            fallbacks: ['Impact'],
          },
        ],
      },
    },
  },
  setup (options, nuxt) {

  },
})
```

你也可以用一个函数，根据 Nuxt 配置动态决定依赖：

```ts
import { defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
  },
  moduleDependencies (nuxt) {
    const dependencies: Record<string, any> = {
      '@nuxtjs/tailwindcss': {
        version: '>=6.0.0',
      },
    }

    // 根据 Nuxt 配置有条件地添加依赖
    if (nuxt.options.experimental?.someFeature) {
      dependencies['@nuxtjs/fontaine'] = {
        optional: true,
      }
    }

    return dependencies
  },
  setup (options, nuxt) {
    // 你的 setup 逻辑会在所有依赖初始化之后运行
  },
})
```

## `installModule`

:callout{type="warning"}
**已弃用：** 请改用 `defineNuxtModule` 中的 [`moduleDependencies`](/docs/api/kit/modules#指定模块依赖) 选项。`installModule` 函数将在未来版本中被移除（或可能变为非阻塞）。
:

以编程方式安装指定的 Nuxt 模块。当你的模块依赖其他模块时这很有帮助。你可以向 `inlineOptions` 传入一个对象作为模块选项，它们会被传给模块的 `setup` 函数。

### 用法

```ts twoslash
import { defineNuxtModule, installModule } from '@nuxt/kit'

export default defineNuxtModule({
  async setup () {
    // 会以 Roboto 字体和 Impact 回退来安装 @nuxtjs/fontaine
    await installModule('@nuxtjs/fontaine', {
      // 模块配置
      fonts: [
        {
          family: 'Roboto',
          fallbacks: ['Impact'],
          fallbackName: 'fallback-a',
        },
      ],
    })
  },
})
```

### 类型

```ts
async function installModule (moduleToInstall: string | NuxtModule, inlineOptions?: any, nuxt?: Nuxt)
```

### 参数

| 属性             | 类型                              | 必填    | 描述                                                                               |
|------------------|-----------------------------------|---------|-----------------------------------------------------------------------------------|
| `moduleToInstall`| `string \| NuxtModule`{lang="ts"} | `true`  | 要安装的模块。可以是一个带有模块名的字符串，也可以是模块对象本身。                |
| `inlineOptions`  | `any`                             | `false` | 一个带有模块选项的对象，会传给模块的 `setup` 函数。                               |
| `nuxt`           | `Nuxt`                            | `false` | Nuxt 实例。如果未提供，会通过 `useNuxt()` 调用从上下文中获取。                    |

### 示例

```ts
import { defineNuxtModule, installModule } from '@nuxt/kit'

export default defineNuxtModule({
  async setup (options, nuxt) {
    // 会以 Roboto 字体和 Impact 回退来安装 @nuxtjs/fontaine
    await installModule('@nuxtjs/fontaine', {
      // 模块配置
      fonts: [
        {
          family: 'Roboto',
          fallbacks: ['Impact'],
          fallbackName: 'fallback-a',
        },
      ],
    })
  },
})
```
