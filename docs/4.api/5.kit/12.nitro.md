Nitro 是一个用于构建超快 Web 服务器的开源 TypeScript 框架。Nuxt 使用 Nitro 作为其服务器引擎。你可以使用 `useNitro` 访问 Nitro 实例（如果你的模块在没有 Nitro 时也应能工作，则使用 `tryUseNitro`），`addServerHandler` 添加服务器处理器，`addDevServerHandler` 添加仅在开发模式下使用的服务器处理器，`addNitroPlugin` 添加插件以扩展 Nitro 的运行时行为，`addRendererPlugin` 在任意服务器构建器下注册渲染钩子，以及 `addPrerenderRoutes` 添加将由 Nitro 预渲染的路由。

## `addServerHandler`

添加一个 Nitro 服务器处理器。如果你想创建服务器中间件或自定义路由，可以使用它。

### 用法

```ts twoslash
import { addServerHandler, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options) {
    const { resolve } = createResolver(import.meta.url)

    addServerHandler({
      route: '/robots.txt',
      handler: resolve('./runtime/robots.get'),
    })
  },
})
```

### 类型

```ts
function addServerHandler (handler: ServerHandlerInput): void
```

### 参数

**handler**：一个包含以下属性的处理器对象：

| 属性        | 类型      | 必填    | 描述                                                                                     |
|-------------|-----------|---------|-----------------------------------------------------------------------------------------|
| `handler`   | `string \| { nuxt?: string, nitro2?: string, nitro3?: string }`  | `true`  | 事件处理器的路径，或者每个服务器 API 一个路径。Nuxt 会注册应用的服务器能够运行的那个实现。                     |
| `route`     | `string`  | `false` | 要精确匹配的路由。以 `/**` 结尾可同时匹配其下方的路径。如果使用空字符串，该处理器会被注册为中间件。                                  |
| `middleware`| `boolean` | `false` | 指定这是一个中间件处理器。中间件会在每个路由上被调用，通常应不返回任何内容以传递给下一个处理器。 |
| `lazy`      | `boolean` | `false` | 使用惰性加载来导入处理器。当你只想按需加载处理器时这很有用。                            |
| `method`    | `string`  | `false` | 路由方法匹配器。如果处理器名称包含方法名，它会被用作默认值。                            |

以 `/**` 结尾的路由也会匹配它的基路径，因此 `route: '/_fonts/**'` 会同时服务于 `/_fonts` 及其下方的所有内容。在 Nitro 2 宿主上，其路由只会匹配基路径之下的路径，因此 Nuxt 会把基路径注册为第二条路由，使同一次注册在两种宿主上表现一致。

这一点不适用于中间件。在 Nitro 2 宿主上，中间件的 `route` 是一个字面的路径前缀：`route: '/admin'` 会对 `/admin` 以及所有以它开头的路径运行，而 `route: '/admin/**'` 只会对以 `/admin/**` 这些字符开头的路径运行。在 Nitro 2 宿主上请把中间件注册在其基路径上。

中间件的 `route` 是区分大小写匹配的，即使页面不是如此。在设置了 `router.options.sensitive: false` 时，用于保护页面的中间件不会因为路由的大小写变体而运行，例如 `/admin` 对应的 `/Admin`（参见[不区分大小写路由中的服务端中间件](/docs/guide/recipes/custom-routing#server-middleware-with-case-insensitive-routing)）。

::read-more{to="/docs/guide/modules/server-compatibility"}
了解何时应为每个服务器 API 注册一个路径，以及你的处理器应针对哪个 key 来编写。
::

### 示例

#### 基础用法

你可以使用 `addServerHandler` 从你的模块添加一个服务器处理器。

::code-group

```ts twoslash [module.ts]
import { addServerHandler, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options) {
    const { resolve } = createResolver(import.meta.url)

    addServerHandler({
      route: '/robots.txt',
      handler: resolve('./runtime/robots.get'),
    })
  },
})
```

```ts twoslash [runtime/robots.get.ts]
import { defineEventHandler } from 'nitro/h3'

export default defineEventHandler(() => {
  return {
    body: `User-agent: *\nDisallow: /`,
  }
})
```

::

当你访问 `/robots.txt` 时，它会返回如下响应：

```txt
User-agent: *
Disallow: /
```

## `addDevServerHandler`

添加一个仅在开发模式下使用的 Nitro 服务器处理器。该处理器不会被包含在生产构建中。

### 用法

```ts twoslash
import { addDevServerHandler, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    addDevServerHandler({
      handler: {
        nuxt: () => new Response(`Response generated at ${new Date().toISOString()}`),
      },
      route: '/_handler',
    })
  },
})
```

### 类型

```ts
function addDevServerHandler (handler: DevServerHandlerInput): void
```

### 参数

**handler**：一个包含以下属性的处理器对象：

| 属性     | 类型           | 必填    | 描述                                                                       |
|----------|----------------|---------|---------------------------------------------------------------------------|
| `handler`| `EventHandler \| { nuxt?: (event: RequestEvent) => unknown, nitro2?: EventHandler, nitro3?: EventHandler }` | `true`  | 事件处理器，或者每个服务器 API 一个处理器。Nuxt 会注册应用的服务器能够运行的那个实现。                                                              |
| `route`  | `string`       | `false` | 要匹配的路由。以 `/**` 结尾可同时匹配其下方的路径。`nitro2` 处理器也会匹配不带 `/**` 的路径之下的路径。如果使用空字符串，该处理器会被注册为中间件。                     |
| `method`  | `string`       | `false` | 要匹配的 HTTP 方法，例如 `'POST'`。在 `nitropack` v2 宿主上，处理器会对所有方法运行。                     |
| `middleware` | `boolean`   | `false` | 在路由处理器之前运行该处理器。不返回任何内容即可把请求传递给下一个处理器。`nitro2` 处理器总是以中间件方式运行。                     |
| `meta`    | `object`       | `false` | 路由元数据，例如 OpenAPI 操作信息。Nitro v3 会把它附加到非中间件的处理器上。                     |

::read-more{to="/docs/guide/modules/server-compatibility#dev-server-handlers"}
了解如何为每个服务器 API 编写开发服务器处理器，以及它们各自匹配哪些路径。
::

### 示例

#### 基础用法

在某些情况下，你可能想专门为了开发目的创建一个服务器处理器，例如 Tailwind 配置查看器。

```ts
import { joinURL } from 'ufo'
import { addDevServerHandler, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  async setup (options, nuxt) {
    const route = joinURL(nuxt.options.app?.baseURL, '/_tailwind')

    // @ts-expect-error - tailwind-config-viewer 没有正确的类型
    const createServer = await import('tailwind-config-viewer/server/index.js').then(r => r.default || r) as any
    const viewerDevMiddleware = createServer({ tailwindConfigProvider: () => options, routerPrefix: route }).asMiddleware()

    addDevServerHandler({ route, handler: viewerDevMiddleware })
  },
})
```

## `useNitro`

返回 Nitro 实例。

::warning
你只能在 `ready` 钩子之后调用 `useNitro()`。
::

::note
对 Nitro 实例配置的更改不会被应用。
::

### 用法

```ts
import { defineNuxtModule, useNitro } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    const resolver = createResolver(import.meta.url)

    nuxt.hook('ready', () => {
      const nitro = useNitro()
      // 对 Nitro 实例做一些处理
    })
  },
})
```

### 类型

```ts
function useNitro (): Nitro
```

## `tryUseNitro`

返回 Nitro 实例；当不存在 Nitro 实例时返回 `undefined`。

在 `ready` 钩子运行之前没有 Nitro 实例；当所配置的
[`server.builder`](/docs/api/nuxt-config#builder-1) 不使用 Nitro 时也完全没有 Nitro 实例，
例如只输出纯客户端 SPA 的构建器。对于那些在没有服务器时也应该继续工作的逻辑，
请使用它而不是 `useNitro()`：在那种情况下，服务器路由、路由规则和预渲染都不存在。

### 用法

```ts
import { defineNuxtModule, tryUseNitro } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options, nuxt) {
    nuxt.hook('ready', () => {
      const nitro = tryUseNitro()
      if (!nitro) {
        // 没有服务器：跳过那些只会在服务器中运行的逻辑
        return
      }
    })
  },
})
```

### 类型

```ts
function tryUseNitro (): Nitro | undefined
```

## `addNitroPlugin`

添加插件以扩展 Nitro 的运行时行为。

::note
在 Nuxt v4.6 之前它名为 `addServerPlugin`。
::

::tip
你可以在 [Nitro 文档](https://nitro.build/guide/plugins) 中阅读更多关于 Nitro 插件的内容。
::

::warning
有必要在你的插件文件中显式地从 `nitro` 导入 `definePlugin`。同样的要求也适用于诸如 `useRuntimeConfig` 之类的实用工具。
::

### 用法

```ts twoslash
import { addNitroPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    const { resolve } = createResolver(import.meta.url)
    addNitroPlugin(resolve('./runtime/plugin.ts'))
  },
})
```

### 类型

```ts
function addNitroPlugin (plugin: string | { nitro2?: string, nitro3?: string }): void
```

### 参数

| 属性    | 类型     | 必填    | 描述                                                                                       |
|--------|----------|---------|-------------------------------------------------------------------------------------------|
| `plugin`| `string \| { nitro2?: string, nitro3?: string }` | `true`  | 插件的路径；对于为每个 nitro 主版本各提供一个实现的模块，则是每个主版本一个路径。该插件必须导出一个默认函数，该函数接收 Nitro 实例作为参数。                     |

### 示例

::code-group

```ts [module.ts]
import { addNitroPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    const { resolve } = createResolver(import.meta.url)
    addNitroPlugin(resolve('./runtime/plugin.ts'))
  },
})
```

```ts [runtime/plugin.ts]
import { definePlugin } from 'nitro'

export default definePlugin((nitroApp) => {
  nitroApp.hooks.hook('request', (event) => {
    console.log('on request', event.req.url)
  })

  nitroApp.hooks.hook('response', async (res) => {
    console.log('on response', await res.text())
  })
})
```

::

## `addRendererPlugin`

向 SSR 渲染器添加一个插件。任何渲染器都会在渲染之前各调用它一次，并由它传入自己在渲染期间调用的钩子。它在任何服务器构建器下都能运行。

::read-more{to="/docs/guide/modules/server-compatibility#renderer-plugins"}
查看渲染器插件如何在每个服务器构建器下运行，以及在不支持它的 Nuxt 版本上的行为。
::

### 用法

```ts twoslash
import { addRendererPlugin, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    const { resolve } = createResolver(import.meta.url)
    addRendererPlugin(resolve('./runtime/server/renderer.ts'))
  },
})
```

### 类型

```ts
function addRendererPlugin (plugin: string | { nuxt?: string, nitro2?: string, nitro3?: string }): void
```

### 参数

| 属性 | 类型     | 必填 | 描述 |
|----------|----------|----------|-------------|
| `plugin` | `string \| { nuxt?: string, nitro2?: string, nitro3?: string }` | `true`   | 渲染器插件的路径；或者在不支持渲染器插件的 Nuxt 版本上，把该渲染器插件作为 `nuxt`，并同时指定改为注册的 Nitro 插件。渲染器插件必须导出一个接收 `{ hooks }` 的默认函数。 |

### 示例

```ts [runtime/server/renderer.ts]
import type { RendererPlugin } from 'nuxt/server'

export default (({ hooks }) => {
  hooks.hook('render:html', (html) => {
    html.head.push('<meta name="my-module" content="enabled">')
  })
}) satisfies RendererPlugin
```

## `addPrerenderRoutes`

添加将由 Nitro 预渲染的路由。

### 用法

```ts
import { addPrerenderRoutes, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'nuxt-sitemap',
    configKey: 'sitemap',
  },
  defaults: {
    sitemapUrl: '/sitemap.xml',
    prerender: true,
  },
  setup (options) {
    if (options.prerender) {
      addPrerenderRoutes(options.sitemapUrl)
    }
  },
})
```

### 类型

```ts
function addPrerenderRoutes (routes: string | string[]): void
```

### 参数

| 属性    | 类型                            | 必填    | 描述                                   |
|--------|---------------------------------|---------|----------------------------------------|
| `routes`| `string \| string[]`{lang="ts"} | `true`  | 要预渲染的一个路由或一组路由。         |

## `addServerImports`

向服务器添加导入。它让你的导入在 Nitro 中可用，而无需手动导入它们。

::warning
如果你想提供一个在服务器和客户端上下文中都能工作、并且可用于 [`shared/`](/docs/directory-structure/shared) 目录的工具函数，那么这个函数必须从同一个源文件导入 [`addImports`](/docs/api/kit/autoimports#addimports) 和 `addServerImports`，并且应具有相同的签名。该源文件不应导入任何上下文特定的内容（即 Nitro 上下文、Nuxt 应用上下文），否则可能会在类型检查时引发错误。
::

### 用法

```ts twoslash
import { addServerImports, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup (options) {
    const names = [
      'useStoryblok',
      'useStoryblokApi',
      'useStoryblokBridge',
      'renderRichText',
      'RichTextSchema',
    ]

    names.forEach(name =>
      addServerImports({ name, as: name, from: '@storyblok/vue' }),
    )
  },
})
```

### 类型

```ts
function addServerImports (dirs: NuxtImport | NuxtImport[]): void
```

### 参数

`imports`：一个对象或一组对象，包含以下属性：

| 属性      | 类型                  | 必填    | 描述                                                                                 |
|-----------|-----------------------|---------|-------------------------------------------------------------------------------------|
| `name`    | `string`              | `true`  | 要被检测的导入名。                                                                  |
| `from`    | `string`              | `true`  | 要从中导入的模块说明符。                                                            |
| `priority`| `number`              | `false` | 导入的优先级；如果多个导入同名，会使用该优先级最高的那一个。                        |
| `disabled`| `boolean`             | `false` | 该导入是否被禁用。                                                                  |
| `meta`    | `Record<string, any>` | `false` | 导入的元数据。                                                                      |
| `type`    | `boolean`             | `false` | 该导入是否为纯类型导入。                                                            |
| `typeFrom`| `string`              | `false` | 生成类型声明时用作 `from` 值。                                                      |
| `as`      | `string`              | `false` | 以该名称导入。                                                                      |

## `addServerImportsDir`

添加一个将由 Nitro 扫描以进行自动导入的目录。

### 用法

```ts twoslash
import { addServerImportsDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  setup (options) {
    const { resolve } = createResolver(import.meta.url)
    addServerImportsDir(resolve('./runtime/server/composables'))
  },
})
```

### 类型

```ts
function addServerImportsDir (dirs: string | string[], opts: { prepend?: boolean }): void
```

### 参数

| 属性   | 类型                            | 必填    | 描述                                                                                   |
|--------|---------------------------------|---------|---------------------------------------------------------------------------------------|
| `dirs` | `string \| string[]`{lang="ts"} | `true`  | 一个或多个要注册供 Nitro 扫描的目录。                                                  |
| `opts` | `{ prepend?: boolean }`         | `false` | 导入目录的选项。如果 `prepend` 为 `true`，该目录会被添加到扫描列表的开头。            |

### 示例

你可以使用 `addServerImportsDir` 添加一个将由 Nitro 扫描的目录。当你想让 Nitro 从自定义服务器目录自动导入函数时，这很有用。

::code-group

```ts twoslash [module.ts]
import { addServerImportsDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  setup (options) {
    const { resolve } = createResolver(import.meta.url)
    addServerImportsDir(resolve('./runtime/server/composables'))
  },
})
```

```ts twoslash [runtime/server/composables/index.ts]
export function useApiSecret () {
  const { apiSecret } = useRuntimeConfig()
  return apiSecret
}
```

::

然后你可以在你的服务器代码中使用 `useApiSecret` 函数：

```ts twoslash [runtime/server/api/hello.ts]
import { defineEventHandler } from 'nitro/h3'

const useApiSecret = (): string => ''
// ---cut---
export default defineEventHandler(() => {
  const apiSecret = useApiSecret()
  // 对该 apiSecret 做一些处理
})
```

## `addServerScanDir`

添加将由 Nitro 扫描的目录。它会检查子目录，这些子目录会被像 `~~/server` 文件夹一样被注册。

::note
只有 `~~/server/api`、`~~/server/routes`、`~~/server/middleware` 和 `~~/server/utils` 会被扫描。
::

### 用法

```ts twoslash
import { addServerScanDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  setup (options) {
    const { resolve } = createResolver(import.meta.url)
    addServerScanDir(resolve('./runtime/server'))
  },
})
```

### 类型

```ts
function addServerScanDir (dirs: string | string[], opts: { prepend?: boolean }): void
```

### 参数

| 属性   | 类型                            | 必填    | 描述                                                                                   |
|--------|---------------------------------|---------|---------------------------------------------------------------------------------------|
| `dirs` | `string \| string[]`{lang="ts"} | `true`  | 一个或多个要注册供 Nitro 作为服务器目录扫描的目录。                                    |
| `opts` | `{ prepend?: boolean }`         | `false` | 导入目录的选项。如果 `prepend` 为 `true`，该目录会被添加到扫描列表的开头。            |

### 示例

你可以使用 `addServerScanDir` 添加一个将由 Nitro 扫描的目录。当你想添加一个自定义服务器目录时这很有用。

::code-group

```ts twoslash [module.ts]
import { addServerScanDir, createResolver, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  meta: {
    name: 'my-module',
    configKey: 'myModule',
  },
  setup (options) {
    const { resolve } = createResolver(import.meta.url)
    addServerScanDir(resolve('./runtime/server'))
  },
})
```

```ts twoslash [runtime/server/utils/index.ts]
export function hello () {
  return 'Hello from server utils!'
}
```

::

然后你可以在你的服务器代码中使用 `hello` 函数。

```ts twoslash [runtime/server/api/hello.ts]
import { defineEventHandler } from 'nitro/h3'

function hello () {
  return 'Hello from server utils!'
}
// ---cut---
export default defineEventHandler(() => {
  return hello() // Hello from server utils!
})
```
