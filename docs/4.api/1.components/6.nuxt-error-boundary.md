::tip
`<NuxtErrorBoundary>` 底层使用了 Vue 的 [`onErrorCaptured`](https://vuejs.org/api/composition-api-lifecycle#onerrorcaptured) 钩子。
::

当默认插槽中的内容抛出错误时，`#error` 插槽会取而代之被渲染。这在服务端渲染和客户端中都有效：服务端错误会使 `#error` 插槽成为 HTML 响应的一部分（状态码为 `200`），并且错误会被传递给客户端，从而水合为相同的状态。在客户端调用 `clearBoundaryError` 之后，默认插槽会重新渲染。

在生产环境中，非 HTTP 错误的服务端错误（例如使用 [`createError`](/docs/api/utils/create-error) 创建的错误）到达 `#error` 插槽时会变成一个通用的 `500` 错误，因此它的消息和 data 不会被发送到浏览器。HTTP 错误则会保留其 `status`、`message` 和 `data`。

::note
服务端捕获由 [`experimental.ssrErrorBoundary`](/docs/guide/going-further/experimental-features#ssrerrorboundary) 选项控制，该选项默认启用。禁用时，边界组件只捕获客户端错误。
::

::warning
边界组件会捕获渲染其默认插槽时抛出的所有错误，包括使用 `fatal: true` 创建的错误。但它不会拦截绕过组件树的错误，例如对 [`showError`](/docs/api/utils/show-error) 的调用、在路由中间件中抛出的错误，或 `useFetch`/`useAsyncData` 的失败（它们的错误通过 `error` 返回而不会被抛出）。由 vapor 组件渲染的默认插槽只能在客户端被捕获。
::

## Props

- `retryOnClient`：当错误是在服务端渲染期间捕获的，在客户端挂载后重新渲染一次默认插槽。适用于只在服务端失败的内容（例如一个访问 `window` 的组件）：HTML 中先返回 `#error` 插槽的内容，随后在浏览器中被真实内容替换。如果默认插槽在客户端也抛出错误，那么 `#error` 插槽会带着客户端错误再次渲染。
  - **类型**：`boolean`
  - **默认值**：`false`

  ```vue [app/pages/example.vue]
  <template>
    <NuxtErrorBoundary retry-on-client>
      <BrokeInSSR />
      <template #error>
        <p>Loading…</p>
      </template>
    </NuxtErrorBoundary>
  </template>
  ```

## Events

- `@error`：当组件的默认插槽抛出错误时触发的事件。对于在服务端渲染期间捕获的错误，它只在服务端触发。

  ```vue [app/app.vue]
  <template>
    <NuxtErrorBoundary @error="logSomeError">
      <!-- ... -->
    </NuxtErrorBoundary>
  </template>
  ```

## Slots

- `#error`：指定发生错误时显示的回退内容。

  ```vue [app/app.vue]
  <template>
    <NuxtErrorBoundary>
      <!-- ... -->
      <template #error="{ error, clearBoundaryError }">
        <p>发生了一个错误：{{ error }}</p>

        <button @click="clearBoundaryError">
          清除错误
        </button>
      </template>
    </NuxtErrorBoundary>
  </template>
  ```

  ::warning
  该插槽同时把 `clearError` 作为 `clearBoundaryError` 的已弃用别名暴露出来。请使用 `clearBoundaryError`：如果模板没有从插槽属性中解构出 `clearError`，那么它调用的其实是自动导入的 [`clearError`](/docs/api/utils/clear-error)，而这会清除**全局**错误。
  ::

## 示例

### 在脚本中访问 `error` 和 `clearBoundaryError`

你可以像下面这样在组件的脚本中访问 `error` 和 `clearBoundaryError` 属性：

```vue [app/app.vue]
<template>
  <NuxtErrorBoundary ref="errorBoundary">
    <!-- ... -->
  </NuxtErrorBoundary>
</template>

<script setup lang="ts">
const errorBoundary = useTemplateRef('errorBoundary')

// errorBoundary.value?.error
// errorBoundary.value?.clearBoundaryError()
</script>
```
