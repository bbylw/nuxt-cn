## 移除模块

- 移除 `@nuxt/nitro`：Bridge 注入了相同的功能

## 更新配置

```ts [nuxt.config.ts]
import { defineNuxtConfig } from '@nuxt/bridge'

export default defineNuxtConfig({
  bridge: {
    nitro: true,
  },
})
```

## 更新你的脚本

你还需要更新 `package.json` 中的脚本，以反映 Nuxt 现在将生成一个 Nitro 服务器作为构建输出这一事实。

### 安装 Nuxi

安装 `nuxi` 作为开发依赖：

:::code-group{sync="pm"}

```bash [npm]
npm install -D nuxi
```

```bash [yarn]
yarn add --dev nuxi
```

```bash [pnpm]
pnpm add -D nuxi
```

```bash [bun]
bun add -D nuxi
```

```bash [deno]
deno add -D npm:nuxi
```

:::

### Nuxi

Nuxt 3 引入了新的 Nuxt CLI 命令 [`nuxi`](/docs/api/commands/add)。按以下方式更新你的脚本，以利用 Nuxt Bridge 更好的支持：

```diff
{
  "scripts": {
-   "dev": "nuxt",
+   "dev": "nuxi dev",
-   "build": "nuxt build",
+   "build": "nuxi build",
-   "start": "nuxt start",
+   "start": "nuxi preview"
  }
}
```

:::tip
如果 `nitro: false`，使用 `nuxt2` 命令。
:::

### 静态目标

如果你在 `nuxt.config` 中设置了 `target: 'static'`，那么你需要确保将构建脚本更新为 `nuxi generate`。

```json [package.json]
{
  "scripts": {
    "build": "nuxi generate"
  }
}
```

### 服务器目标

对于所有其他情况，你可以使用 `nuxi build` 命令。

```json [package.json]
{
  "scripts": {
    "build": "nuxi build",
    "start": "nuxi preview"
  }
}
```

## 从 Git 中排除已构建的 Nitro 文件夹

将 `.output` 文件夹添加到 `.gitignore` 文件中。

## 确保一切顺利

✔️ 尝试使用 `nuxi dev` 和 `nuxi build`（或 `nuxi generate`）看看一切是否顺利。
