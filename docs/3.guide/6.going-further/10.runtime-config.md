## 暴露配置

要将配置和环境变量暴露给应用的其余部分，你需要在 [`nuxt.config`](/docs/directory-structure/nuxt-config) 文件中，使用 [`runtimeConfig`](/docs/api/nuxt-config#runtimeconfig-1) 选项来定义运行时配置。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    // 仅在服务端可用的私有密钥
    apiSecret: '123',
    // public 内的键，也会被暴露到客户端
    public: {
      apiBase: '/api',
    },
  },
})
```

当把 `apiBase` 添加到 `runtimeConfig.public` 时，Nuxt 会把它添加到每个页面的 payload 中。我们可以在客户端和浏览器中通用地访问 `apiBase`。

```ts
const runtimeConfig = useRuntimeConfig()

console.log(runtimeConfig.apiSecret)
console.log(runtimeConfig.public.apiBase)
```

:::tip
公共运行时配置在 Vue 模板中可通过 `$config.public` 访问。
:::

### 应用密钥（Application Secret）

以 `app` 为前缀的运行时配置键为 Nuxt 保留（目前是 `runtimeConfig.app` 和 `runtimeConfig.appSecret`）。请不要将它们用于你自己的值。

Nuxt 提供了一个私有的 `runtimeConfig.appSecret` 作为应用的根密钥。模块和服务端特性使用 [`deriveSecret`](/docs/guide/going-further/server-imports#deriving-secrets) 从它派生出各自的密钥，[会话辅助函数](/docs/guide/going-further/server-imports#sessions)默认也会使用由它派生的一个密钥来密封（seal）会话。该值默认为空字符串，只在服务端可用，并且你可以通过 `NUXT_APP_SECRET` 设置它，而无需在 `nuxt.config` 中声明这个键。

生成一个至少包含 32 随机字节的密钥：

```bash [Terminal]
openssl rand -base64 32
```

:::important
为每个环境使用不同的值，但要在该环境的各次部署和各服务器实例之间保持稳定。更改该值会使依赖它的任何会话或签名失效。
:::

在开发模式下，只有当 `appSecret` 未设置时，Nuxt 才会生成一个随机密钥并把它存进 `.nuxt/app-secret`，因此依赖它的特性无需任何配置即可工作。已配置的值总是原样使用。当使用生成的值派生出某个密钥时，Nuxt 会在第一次使用时打印一条警告。构建时永远不会生成密钥：请在你部署到的每个环境中设置 `NUXT_APP_SECRET`。

除非有模块或服务端特性使用它，否则 Nuxt 并不要求必须设置 `NUXT_APP_SECRET`。

### 序列化

你的运行时配置在被传入 Nitro 之前会被序列化。这意味着任何无法被序列化然后再反序列化的内容（例如函数、Set、Map 等），都不应该设置在你的 `nuxt.config` 中。

与其从 `nuxt.config` 中将不可序列化的对象或函数传入你的应用，你可以将这段代码放到 Nuxt 或 Nitro 插件、或者中间件中。

### 环境变量

提供配置最常见的方式是使用环境变量。

:::note
Nuxt CLI 在开发、构建和生成阶段内置了对读取你的 `.env` 文件的支持。但当你运行已构建好的服务器时，**你的 `.env` 文件不会被读取**。
:read-more{to="/docs/directory-structure/env"}
:::

运行时配置值**会在运行时被匹配的环境变量自动替换**。

有两个关键要求：

1. 自定义的运行时配置变量必须在你的 `nuxt.config` 中定义。这确保了任意的环境变量不会被暴露给你的应用代码。

1. 只有特定命名的环境变量可以覆盖一个运行时配置属性。也就是以 `NUXT_` 开头的大写环境变量，并使用 `_` 来分隔键名和大小写变化。

:::warning
将 `runtimeConfig` 的默认值设置为*不同名称的环境变量*（例如将 `myVar` 设置为 `process.env.OTHER_VARIABLE`），只会在构建时生效，并在运行时失效。
建议使用与你 `runtimeConfig` 对象结构相匹配的环境变量。
:::

环境变量的值会被转换为它们所替换值的类型：

| 默认值的类型 | 环境变量 | 结果 |
| --- | --- | --- |
| `string` | `NUXT_MY_VAR=4848e0` | `'4848e0'` |
| `number` | `NUXT_MY_VAR=8080` | `8080` |
| `boolean` | `NUXT_MY_VAR=false` | `false`（`true`、`1`、`0`、`yes`、`no`、`on` 和 `off` 同样有效） |
| 数组 | `NUXT_MY_VAR='["value"]'` | `['value']` |
| 对象 | `NUXT_MY_VAR='{"key":"value"}'` | `{ key: 'value' }`，合并覆盖默认值 |

如果默认值只是一个普通的 `null` 或 `undefined`，它会被替换为空字符串，因此该值会以字符串形式被设置。要想在保留 `null` 默认值的同时仍然把变量强制转换为其它类型，请使用形如 `z.number().nullable().default(null)` 的 schema。

对象的嵌套键也可以单独设置，例如用 `NUXT_SESSION_MAX_AGE` 设置 `runtimeConfig.session.maxAge`。对于不能为空字符串的键，空的环境变量值会被忽略。

如果某个环境变量无法被转换（例如为数值型的 `port` 设置 `NUXT_PORT=abc`），服务器将不会启动。若要声明某个值的类型而不给它默认值，请参见[使用 Schema 校验](#使用-schema-校验)。

:::tip{icon="i-lucide-video" to="https://youtu.be/_FYV5WfiWvs" target="_blank"}
观看 Alexander Lichter 的视频，展示开发者使用 runtimeConfig 时最常犯的错误。
:::

#### 示例

```ini [.env]
NUXT_API_SECRET=api_secret_token
NUXT_PUBLIC_API_BASE=https://nuxtjs.org
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: '', // 可以被 NUXT_API_SECRET 环境变量覆盖
    public: {
      apiBase: '', // 可以被 NUXT_PUBLIC_API_BASE 环境变量覆盖
    },
  },
})
```

### 使用 Schema 校验

`runtimeConfig` 中的任何值都可以是一个 [Standard Schema](https://standardschema.dev)，并且同时实现了 [Standard JSON Schema](https://standardschema.dev/json-schema)，例如来自 [Zod](https://zod.dev) 或 [ArkType](https://arktype.io) 的 schema，或者用 `toStandardJsonSchema()` 包裹过的 [Valibot](https://valibot.dev) schema。schema 会设定该值的类型，而它自身的默认值（如果存在）会被用作默认值。

```ts [nuxt.config.ts]
import { z } from 'zod'

export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: z.string(),
    session: z.object({
      maxAge: z.number().int().default(60 * 60),
      secure: z.boolean().default(true),
    }),
    public: {
      mode: z.enum(['preview', 'production']).default('production'),
    },
  },
})
```

一个没有默认值的值（例如上面的 `apiSecret`）是必需的。Nuxt 会在构建期间就缺失的值发出警告，而在它被提供（此处通过 `NUXT_API_SECRET`）之前服务器不会启动。在预渲染期间，只有*读取*缺失的值才会抛出错误，因此依赖它的页面会预渲染失败，而其他页面不受影响。可以使用 `z.string().optional()` 或你所用 schema 库中的等价写法把一个值变为可选。

这个 schema 也可以用于整个 `runtimeConfig`、写在[层（layer）](/docs/getting-started/layers)的 `nuxt.config` 中，或由模块通过 [`updateRuntimeConfig()`](/docs/api/kit/runtime-config#schemas) 设置。在更上层的层里、或在你的 `nuxt.config` 中设置的普通值，会成为更下方声明的 schema 的默认值。

当服务器启动时，Nuxt 会依据每个 schema 的一份紧凑描述来检查运行时配置：每个值的类型、哪些值是必需的，以及枚举和联合类型所允许的值。在开发模式和构建期间，Nuxt 还会对那些与当时使用的环境变量不匹配的值发出警告。

:::note
schema 本身不会包含在你的服务端包中。细化约束（refinements），例如最小长度或 URL 格式，不会被检查；转换（transforms）也不受支持。
:::

## 读取配置

### Vue 应用

在 Nuxt 应用的 Vue 部分，你需要调用 [`useRuntimeConfig()`](/docs/api/composables/use-runtime-config) 来访问运行时配置。

:::important
客户端和服务端的行为不同：

- 在客户端，只有 `runtimeConfig.public` 和 `runtimeConfig.app`（Nuxt 内部使用）中的键可用，并且该对象既可读写也具有响应性。

- 在服务端，整个运行时配置都可用，但你应当把它当作只读对象。它是一个在所有请求之间共享的单一对象，因此在渲染某个请求时做出的修改会对之后的所有请求可见。在开发模式下，如果它在服务端渲染期间被修改，Nuxt 会记录一条警告。
:::

```vue [app/pages/index.vue]
<script setup lang="ts">
const config = useRuntimeConfig()

console.log('Runtime config:', config)
if (import.meta.server) {
  console.log('API secret:', config.apiSecret)
}
</script>

<template>
  <div>
    <div>检查开发者控制台！</div>
  </div>
</template>
```

:::caution
**安全提示：** 小心不要通过渲染它们或将它们传入 `useState` 来把运行时配置的键暴露到客户端。
:::

### 插件

如果你想在任意（自定义）插件中使用运行时配置，可以在你的 `defineNuxtPlugin` 函数内部使用 [`useRuntimeConfig()`](/docs/api/composables/use-runtime-config)。

```ts [app/plugins/config.ts]
export default defineNuxtPlugin((nuxtApp) => {
  const config = useRuntimeConfig()

  console.log('API base URL:', config.public.apiBase)
})
```

### 服务端路由

你也可以在服务端路由中使用 `useRuntimeConfig` 访问运行时配置。

```ts [server/api/test.ts]
export default defineEventHandler(async (event) => {
  const { apiSecret } = useRuntimeConfig()
  const result = await $fetch('https://my.api.com/test', {
    headers: {
      Authorization: `Bearer ${apiSecret}`,
    },
  })
  return result
})
```

## 为运行时配置添加类型

Nuxt 会根据每个值的类型，或根据它的 schema，为你的运行时配置生成类型。当服务器启动时，环境变量会被转换成相同的类型，因此生成的类型描述的就是你的应用实际接收到的值。

如果某个值的类型无法由它的默认值描述出来——例如没有默认值的值、枚举或联合类型——请[使用 schema 来声明它](#使用-schema-校验)，而不是去增强 `RuntimeConfig` 接口：

```ts [nuxt.config.ts]
import { z } from 'zod'

export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: z.string(),
    public: {
      apiBase: z.url().default('/api'),
    },
  },
})
```

:::warning
从 `nuxt/schema` 增强 `RuntimeConfig` 或 `PublicRuntimeConfig` 只会改变类型。值仍然会按照各自的默认值进行转换，因此一个被增强的类型可能描述了一个你的应用永远不会收到的值。
:::
