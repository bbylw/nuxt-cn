---
title: "Nightly 发布通道"
description: "nightly 发布通道允许使用直接从仓库最新提交构建的 Nuxt。"
---

Nuxt 每天都会合并提交、改进和 bug 修复。你可以选择提前测试它们，赶在下次发布之前。

当一个提交被合并进 [nuxt/nuxt](https://github.com/nuxt/nuxt) 的 `main` 分支，并**通过所有测试**后，我们会使用 GitHub Actions 触发一次自动的 npm 发布。

你可以使用这些「nightly」发布来对新特性和变更进行 beta 测试。

这些「nightly」发布的构建和发布方法、质量与稳定版相同。唯一的区别是你应该经常查看 GitHub 仓库以获取更新。在审查过程和自动化测试中可能有一定几率遗漏回归问题。因此，我们内部也使用这个通道，在每次发布前对所有内容进行双重检查。

:::note
仅在 nightly 发布通道上可用的特性，在文档中会带有警示标记。
:::

:::warning
`latest` nightly 发布通道目前跟踪的是 Nuxt v4 分支，这意味着现在尤其可能出现破坏性变更——务必小心！你可以选择使用 `"nuxt": "npm:nuxt-nightly@3x"` 来订阅 3.x 分支的 nightly 发布。
:::

## 加入（Opting In）

更新 `package.json` 中的 `nuxt` 依赖：

```diff [package.json]
{
  "devDependencies": {
--    "nuxt": "^4.0.0"
++    "nuxt": "npm:nuxt-nightly@latest"
  }
}
```

删除 lockfile（`package-lock.json`、`yarn.lock`、`pnpm-lock.yaml`、`bun.lock` 或 `bun.lockb`）并重新安装依赖。

## 退出（Opting Out）

更新 `package.json` 中的 `nuxt` 依赖：

```diff [package.json]
{
  "devDependencies": {
--    "nuxt": "npm:nuxt-nightly@latest"
++    "nuxt": "^4.0.0"
  }
}
```

删除 lockfile（`package-lock.json`、`yarn.lock`、`pnpm-lock.yaml`、`bun.lock` 或 `bun.lockb`）并重新安装依赖。

## 使用 Nightly 版 `@nuxt/cli`

要试用 [nuxt/cli](https://github.com/nuxt/cli) 的最新版本：

```bash [Terminal]
npx @nuxt/cli-nightly@latest [command]
```
