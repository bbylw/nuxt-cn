title: "特性开关"
description: "启用或禁用可选的 Nuxt 特性，以解锁新的可能性。"
---

Nuxt 的一些特性是按需启用的，也可以根据你的需求禁用。

## `features`

### devLogs

在开发时，将服务端日志流式传输到客户端。这些日志可以在 `dev:ssr-logs` 钩子中处理。

默认情况下，这在开发模式下启用（当测试模式未激活时）。

如果设为 `silent`，日志将不会打印到浏览器控制台。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  features: {
    devLogs: true,
  },
})
```

### inlineStyles

在渲染 HTML 时内联样式。目前仅在使用 Vite 时可用。

你也可以传入一个函数，该函数接收 Vue 组件的路径，并返回一个布尔值，指示是否内联该组件的样式。

它默认为 `(id) => id.includes('.vue')`。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  features: {
    inlineStyles: false, // 或传入一个函数来决定是否内联
  },
})
```

### noScripts

关闭 Nuxt 脚本和 JavaScript 资源提示的渲染，让页面以纯 HTML 和 CSS 交付。

可能的取值：

- `false`（默认）：正常渲染脚本。
- `'production'`（或 `true`，会被规范化为 `'production'`）：仅在生产构建中省略脚本，因此在 `nuxt dev` 中热模块替换（HMR）等开发特性可以继续工作。
- `'all'`：在开发和生产中都省略脚本。

不提供脚本的页面通过整页加载进行导航。为了保持导航速度，Nuxt 会在这些页面上发出一个[推测规则（speculation rules）](https://developer.mozilla.org/en-US/docs/Web/API/Speculation_Rules_API)标签，让支持的浏览器在用户点开链接之前就预取并预渲染目标页面。该标签是声明式的 JSON，不执行任何 JavaScript。规则的作用范围限定在你的页面路由（这些路由可以安全地 `GET`）而不是所有同源链接，因此指向服务端路由（例如 `/logout`）的链接绝不会被推测性地请求。全捕获页面（例如 `pages/[...slug].vue`）会匹配每一个路径，这又把范围放大回了所有同源链接。

客户端*导航到*被 `noScripts` 路由规则覆盖的路由时，会改为触发一次完整文档加载，从而该路由确实是无脚本地提供服务，而不是由客户端路由器渲染。那些在构建时即可确定被此类规则覆盖路由的页面，也会被完全从客户端包中排除。

带脚本的页面会发出自己的推测规则标签，其作用范围限定在 `noScripts` 的路由模式上，因此浏览器可以在整页导航到这些目标之前预取并预渲染它们。当启用视图过渡（view transitions）时，这些页面还会选择加入声明式的跨文档视图过渡，以便为导航过程添加动画。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  features: {
    noScripts: 'production', // 或 'all' | false
  },
})
```

你也可以通过 `noScripts`[路由规则](/docs/guide/concepts/rendering#hybrid-rendering) 按路由禁用脚本，它在所有模式下都会生效：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/blog/**': { noScripts: true },
  },
})
```

当 `noScripts` 应用于某个被渲染的页面时，以下内容会从 HTML 中省略：

- Nuxt 入口 `<script>` 标签
- 入口分块（entry chunk）的 import map
- 内联的 payload `<script>`（以及启用 payload 提取时的 payload 预加载链接）
- JavaScript 资源提示（用于 JS 分块的 `preload` 和 `prefetch` 链接）

CSS 不受影响：样式表链接和内联样式仍会渲染，因此页面外观完全一致。页面只是永远不会水合，这意味着页面上没有任何内容是可交互的。

有几处交互行为需要留意：

- 带有 `noScripts` 路由规则的路由始终使用缓冲（非流式）渲染器渲染。
- [服务端组件](/docs/guide/concepts/server-components) 若只渲染静态 HTML，则工作正常；但使用 `nuxt-client` 水合的组件以及可交互的孤岛（island）插槽依赖内联脚本来重定位传送（teleport）的内容，因此它们在 `noScripts` 路由上不会变得可交互。出于这个原因，当 `features.noScripts` 在全应用范围设置且组件孤岛处于启用状态时，Nuxt 也会回退到缓冲渲染。

:::read-more{to="/docs/guide/recipes/mostly-static-sites"}
请参见近乎静态网站（mostly-static sites）配方，了解如何把 `noScripts` 与预渲染、孤岛以及延迟水合结合起来使用。
:::

## `future`

还有一个 `future` 命名空间，用于提前选择加入将在未来（可能是大版本）框架中成为默认的新特性。

:::note
`future.compatibilityVersion` 在 Nuxt 5 中始终解析为 `5`。若要在 Nuxt 4 上选择加入 Nuxt 5 的行为，请参阅 [Nuxt 4 文档](https://nuxt.com/docs/4.x/getting-started/upgrade#testing-nuxt-5)。
:::

### multiApp

此选项可提前访问实验性的多应用支持。你可以关注 [跟踪 issue #21635](https://github.com/nuxt/nuxt/issues/21635) 来了解 Nuxt 中多应用支持的进展。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  future: {
    multiApp: true,
  },
})
```

### typescriptBundlerResolution

此选项为 TypeScript 启用 'Bundler' 模块解析模式，这是像 Nuxt 和 [Vite](https://vite.dev/guide/performance#reduce-resolve-operations) 这样的框架的推荐设置。

它在使用带有 `exports` 的现代库时改进了类型支持。

参见 [原始的 TypeScript pull request](https://github.com/microsoft/TypeScript/pull/51669)。

你可以将其设为 false 以使用传统的 'Node' 模式，这是 TypeScript 的默认模式。

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  future: {
    typescriptBundlerResolution: false,
  },
})
```
