description: "Nuxt 会自动导入组件、组合式函数、辅助函数和 Vue API。"
---

Nuxt 会自动导入组件、组合式函数以及 [Vue.js API](https://vuejs.org/api/)，让你可以在整个应用中直接使用而无需显式导入它们。

```vue twoslash [app/app.vue]
<script setup lang="ts">
const count = ref(1) // ref 是自动导入的
</script>
```

得益于其约定式的目录结构，Nuxt 可以自动导入你的 [`app/components/`](/docs/directory-structure/app/components)、[`app/composables/`](/docs/directory-structure/app/composables) 和 [`app/utils/`](/docs/directory-structure/app/utils)。

与传统的全局声明不同，Nuxt 保留了类型、IDE 补全和提示，并且**只会包含你生产代码中实际用到的内容**。

:::note
在文档中，每个没有被显式导入的函数都是被 Nuxt 自动导入的，可以直接原样在你的代码中使用。你可以在 [API 章节](/docs/api) 找到自动导入组件、组合式函数和工具函数的参考。
:::

:::note
在 [`server`](/docs/directory-structure/server) 目录中，Nuxt 会自动导入从 `server/utils/` 导出的函数和变量。
:::

:::note
你还可以通过配置 `nuxt.config` 文件中的 [`imports`](/docs/api/nuxt-config#imports) 部分，从自定义文件夹或第三方包自动导入函数。
:::

## 内置自动导入

Nuxt 自动导入函数和组合式函数，用于执行[数据获取](/docs/getting-started/data-fetching)、访问[应用上下文](/docs/api/composables/use-nuxt-app)和[运行时配置](/docs/guide/going-further/runtime-config)、管理[状态](/docs/getting-started/state-management)，或定义组件和插件。

```vue twoslash
<script setup lang="ts">
/* useFetch() 是自动导入的 */
const { data, refresh, status } = await useFetch('/api/hello')
</script>
```

Vue 暴露了响应式 API（如 `ref` 或 `computed`），以及生命周期钩子和辅助函数，这些都被 Nuxt 自动导入。

```vue twoslash
<script setup lang="ts">
/* ref() 和 computed() 是自动导入的 */
const count = ref(1)
const double = computed(() => count.value * 2)
</script>
```

### Vue 与 Nuxt 组合式函数

<!-- TODO: 在 https://github.com/nuxt/nuxt/issues/14723 之后移到单独页面并添加更多信息 -->

当你使用 Vue 和 Nuxt 提供的内置 Composition API 组合式函数时，请注意其中许多都依赖于在正确的**上下文**中被调用。

在组件生命周期中，Vue 通过一个全局变量追踪当前组件的临时实例（类似地，Nuxt 追踪 `nuxtApp` 的临时实例），然后在同一个 tick 中取消设置。这在服务端渲染时至关重要，既能避免跨请求状态污染（在两个用户之间泄漏共享引用），也能避免不同组件之间的泄漏。

这意味着（极少数例外）你无法在 Nuxt 插件、Nuxt 路由中间件或 Vue setup 函数之外使用它们。除此之外，你必须同步地使用它们——也就是说，不能在调用组合式函数之前使用 `await`，除非在 `<script setup>` 块内、在使用 `defineNuxtComponent` 声明的组件的 setup 函数中、`defineNuxtPlugin` 中或 `defineNuxtRouteMiddleware` 中，在这些地方我们进行了转换以在 `await` 之后仍然保持同步上下文。

如果你收到类似 `Nuxt instance is unavailable`（Nuxt 实例不可用）的错误消息，那么很可能意味着你在 Vue 或 Nuxt 生命周期的错误位置调用了 Nuxt 组合式函数。

:video-accordion{title="观看 Alexander Lichter 关于避免 'Nuxt instance is unavailable' 错误的视频" videoId="ofuKRZLtOdY"}

:::tip
当在一个非 SFC 组件中使用需要 Nuxt 上下文的组合式函数时，你需要用 `defineNuxtComponent` 而非 `defineComponent` 来包裹你的组件
:::

:::read-more{to="/docs/guide/going-further/experimental-features#asynccontext" icon="i-lucide-star"}
查看 `asyncContext` 实验性特性，以在异步函数中使用 Nuxt 组合式函数。
:::

:::read-more{to="https://github.com/nuxt/nuxt/issues/14269#issuecomment-1397352832" target="_blank"}
在此 GitHub 评论中查看完整解释。
:::

**会出错的代码示例：**

```ts twoslash [composables/example.ts]
// 试图在组合式函数之外访问运行时配置
const config = useRuntimeConfig()

export const useMyComposable = () => {
  // 在这里访问运行时配置
}
```

**可正常工作的代码示例：**

```ts twoslash [composables/example.ts]
export const useMyComposable = () => {
  // 因为你的组合式函数在生命周期的正确位置被调用，
  // useRuntimeConfig 在这里能够正常工作
  const config = useRuntimeConfig()

  // ...
}
```

## 基于目录的自动导入

Nuxt 会直接自动导入在已定义目录中创建的文件：

- `app/components/` 用于 [Vue 组件](/docs/directory-structure/app/components)。
- `app/composables/` 用于 [Vue 组合式函数](/docs/directory-structure/app/composables)。
- `app/utils/` 用于辅助函数和其他工具。

:link-example{to="/docs/examples/features/auto-imports"}

:::warning
**自动导入的 `ref` 和 `computed` 在组件的 `<template>` 中不会被解包。** :br
这是因为 Vue 对非模板顶层 ref 的处理方式所致。你可以在 [Vue 文档](https://vuejs.org/guide/essentials/reactivity-fundamentals#caveat-when-unwrapping-in-templates) 中阅读更多内容。
:::

### 显式导入

Nuxt 通过 `#imports` 别名暴露每一个自动导入，在需要时可以显式导入：

<!-- TODO:twoslash: Twoslash 尚不支持 tsconfig 路径 -->

```vue
<script setup lang="ts">
import { computed, ref } from '#imports'

const count = ref(1)
const double = computed(() => count.value * 2)
</script>
```

### 禁用自动导入

如果你想禁用自动导入组合式函数和工具函数，可以在 `nuxt.config` 文件中将 `imports.autoImport` 设为 `false`。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  imports: {
    autoImport: false,
  },
})
```

这会完全禁用自动导入，但你仍然可以使用来自 `#imports` 的[显式导入](/docs/guide/concepts/auto-imports#explicit-imports)。

### 部分禁用自动导入

如果你想让像 `ref` 这样框架特定的函数保持自动导入，但希望禁用你自己代码的自动导入（例如自定义组合式函数），可以在你的 `nuxt.config.ts` 中将 `imports.scan` 设为 `false`：

```ts
export default defineNuxtConfig({
  imports: {
    scan: false,
  },
})
```

在此配置下：
- 像 `ref`、`computed` 或 `watch` 这样的框架函数仍然无需手动导入即可工作。
- 自定义代码，例如组合式函数，需要在你的文件中手动导入。

:::warning
**注意：** 此设置有若干限制：
- 如果你用 layers 来组织项目，你将需要显式地从每个 layer 导入组合式函数，而不能依赖自动导入。
- 这会破坏 layer 系统的覆盖特性。如果你使用 `imports.scan: false`，请确保你理解这个副作用，并相应地调整你的架构。
:::

## 自动导入的组件

Nuxt 还会自动从你的 `~/components` 目录导入组件，尽管这与自动导入组合式函数和工具函数的配置是分开的。

:read-more{to="/docs/directory-structure/app/components"}

要禁用从你自己的 `~/components` 目录自动导入组件，你可以将 `components.dirs` 设为一个空数组（但请注意这不会影响模块添加的组件）。

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  components: {
    dirs: [],
  },
})
```

## 从第三方包自动导入

Nuxt 也允许从第三方包自动导入。

:::tip
如果你正在使用该包的 Nuxt 模块，该模块很可能已经为那个包配置好了自动导入。
:::

例如，你可以这样启用从 `vue-i18n` 包自动导入 `useI18n` 组合式函数：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  imports: {
    presets: [
      {
        from: 'vue-i18n',
        imports: ['useI18n'],
      },
    ],
  },
})
```
