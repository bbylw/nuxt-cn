title: '服务端组件'
description: 只在服务端渲染单个组件，把它的 JavaScript 留在客户端 bundle 之外。
---

Nuxt 默认在服务器上渲染你的应用，但它随后会把每个组件的 JavaScript 发送到浏览器，并水合整个页面。对于内容很重、在客户端从不变化的组件（markdown 渲染、语法高亮、CMS 输出），这是白费功夫：用户下载、解析并执行的代码，其唯一工作只是复现页面上已经存在的 HTML。

服务端组件（也称孤岛（island）组件）把这件事颠倒过来。服务端组件在服务端渲染，它的 HTML 被嵌入页面，而它的 JavaScript 一点也不会发送到客户端。它的依赖（一个 markdown 解析器、一个高亮库）同样留在服务端。

## 启用服务端组件

组件孤岛由 [`experimental.componentIslands`](/docs/guide/going-further/experimental-features#componentislands) 控制。默认值是 `'auto'`，只要你的应用中出现了一个服务端组件或孤岛，它就会自动启用该特性，因此在多数情况下你不需要任何配置。

如果你需要远程孤岛或选择性客户端水合，请显式设置该选项：

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    componentIslands: {
      selectiveClient: true, // 或 'deep'，用于启用 `nuxt-client`
      remoteIsland: false, // 允许渲染来自远程来源的孤岛
    },
  },
})
```

:::read-more{icon="i-simple-icons-github" to="https://github.com/nuxt/nuxt/issues/19772" target="_blank"}
服务端组件仍然被标记为实验性的。你可以在 GitHub 上关注它的路线图。
:::

## `.server.vue` 组件

给一个组件加上 `.server` 后缀，就能使它成为一个独立的服务端组件：

```bash [Directory Structure]
-| app/
---| components/
-----| HighlightedMarkdown.server.vue
```

像使用其它组件一样使用它：

```vue [app/pages/example.vue]
<template>
  <div>
    <!--
      在服务端渲染；markdown 解析和高亮
      库不会包含进你的客户端 bundle
     -->
    <HighlightedMarkdown markdown="# Headline" />
  </div>
</template>
```

`~/components/islands/` 中的组件同样会被注册为孤岛，并可以直接用 [`<NuxtIsland>`](/docs/api/components/nuxt-island) 渲染，例如对于 `~/components/islands/MyIsland.vue` 使用 `<NuxtIsland name="MyIsland" />`。

你也可以把一个 `.server.vue` 组件与同名的 `.client.vue` 组件配成一对，以获得[独立的服务端与客户端实现](/docs/directory-structure/app/components#paired-with-a-client-component)。这种情况下该组件并不是孤岛：客户端那一半会照常水合。

:::warning
服务端组件（以及孤岛）必须只有一个根元素。（HTML 注释也被视为元素。）
:::

## 孤岛是如何渲染的

服务端组件在底层使用了 [`<NuxtIsland>`](/docs/api/components/nuxt-island)。渲染一个孤岛会向一个专用的孤岛端点发起请求，该请求会：

- 在服务端**新建一个独立的 Vue 应用**，只用来渲染那个组件
- 创建一个「孤岛上下文（island context）」，你可以在孤岛内部通过 `nuxtApp.ssrContext.islandContext` 访问它
- 再次运行你的插件，除非它们设置了 `env: { islands: false }`（对象语法的插件）

由于孤岛与你的应用其余部分是隔离的：

- 你无法在页面与孤岛之间共享状态（provide/inject、Pinia、`useState`）；请改用 props 传递数据
- 孤岛内的 [`useRoute()`](/docs/api/composables/use-route) 反映的是孤岛自己的请求，而不是用户所在页面的路由。如果一个孤岛需要路由信息，请显式传入它，既可以作为 props，也可以通过 `<NuxtIsland>` 的 `context` prop（在孤岛内从 `nuxtApp.ssrContext.islandContext` 读取）
- 渲染孤岛时不会运行路由中间件

props 会被序列化并作为 **GET 查询参数**发送。这让孤岛响应可以被缓存，但这也意味着：

- props 必须可 JSON 序列化
- props 受 URL 长度限制，因此避免传递大量数据
- props 可能会出现在服务端访问日志、CDN 缓存和 `Referer` 头中

:::note
因为 props 来自请求（URL 查询或 body），请把它们当作不受信任的输入。Nuxt 会拒绝最有可能被无意泄露的 props：组件未声明的顶层 `as`（未声明的 prop 会作为属性渗透到孤岛的根元素上），以及在启用 `vue.runtimeCompiler` 时 props 中任意位置的 `template`。除此之外，避免把你未校验过的 props 喂给动态组件解析（`<component :is>`{lang=vue}、`h()`、`resolveDynamicComponent()`，或多态的 `as` / `asChild` prop），因为字符串可以解析为任何已注册的组件或 HTML 元素。

把 props 视为不受信任也包括它们的大小：在用数值或数组 prop 去驱动 `v-for` 或其它会随其值增长的工作之前，先校验或钳制它们。在孤岛渲染中，Nuxt 会把数值型的 `v-for` 来源上限设为 10000 次迭代，但这只是兜底措施，不是校验。

组件未声明的 props 会作为属性渗透到它的单个根元素上，因此一个根元素是多态组件（例如来自 `reka-ui` / `@nuxt/ui`）的孤岛可能会收到你未曾绑定的属性。请在这类孤岛上设置 `defineOptions({ inheritAttrs: false })`{lang=ts}，或者声明你接受的 props。与任何 Vue 组件一样，渗透的属性包含 `onclick`、`onfocus` 这样的事件处理属性，浏览器会把它们当作 JavaScript 来执行，所以不要把一个你无法控制的对象（例如 `route.query`）展开到服务端组件或 `<NuxtIsland>`{lang=vue} 的 `props` 上。

要根据调用方传入的输入来切换组件，请通过一个已导入组件的允许列表映射一个判别值，而不是把原始 prop 传进去：

```vue
<script setup lang="ts">
import type { Component } from 'vue'
import CardA from './CardA.vue'
import CardB from './CardB.vue'

const props = defineProps<{ variant: string }>()
const allowed: Record<string, Component> = { a: CardA, b: CardB }
const component = allowed[props.variant] ?? CardA
</script>

<template>
  <component :is="component" />
</template>
```
:::

修改孤岛的 props 会触发一次网络请求，在服务器上重新渲染该组件并就地更新它的 HTML。

:::read-more{to="/docs/api/components/nuxt-island"}
阅读完整的 `<NuxtIsland>` API 文档，包括 props、插槽、事件和已知限制。
:::

## 使用 `nuxt-client` 的选择性水合

孤岛默认是静态的，但你可以通过给其中的单个组件添加 `nuxt-client` 属性来水合它们。这需要启用 `experimental.componentIslands.selectiveClient`。

```vue [app/components/ServerWithClient.server.vue]
<template>
  <div>
    <HighlightedMarkdown markdown="# Headline" />
    <!-- Counter 会在客户端被加载并水合 -->
    <Counter
      nuxt-client
      :count="5"
    />
  </div>
</template>
```

被标记了 `nuxt-client` 的组件会作为孤岛的一部分在服务端渲染，随后由主客户端应用水合。只有它自己的 chunk 会发送到客户端；孤岛的其余部分仍保持静态。

设置 `selectiveClient: 'deep'` 还会额外允许向 `nuxt-client` 组件传递插槽。这些插槽会在服务端渲染，并且在客户端**不可交互**。

:::warning
只将 `nuxt-client` 用在本地的 `.vue` 单文件组件上。像 [`<NuxtLink>`](/docs/api/components/nuxt-link) 这样的内置组件会跳过孤岛转换。在客户端导航之后，你可能会看到 `Failed to locate Teleport target`，或者链接消失且没有任何错误。请把内置组件包裹在你自己的 `.vue` 文件里，并把 `nuxt-client` 放在那个包装组件上。参见 [#29251](https://github.com/nuxt/nuxt/issues/29251) 和 [#26002](https://github.com/nuxt/nuxt/issues/26002)。
:::

## 插槽

如果孤岛中声明了插槽，就可以向孤岛组件传递插槽。插槽内容由父级提供，因此它属于主客户端应用，并且**是**可交互的（它被包裹在一个带 `display: contents;` 的 `<div>` 中）。

`<NuxtIsland>` 预留了 `#fallback` 插槽，用来指定在孤岛加载之前（设置了 `lazy` 时）渲染的内容，或在获取孤岛失败时渲染的内容。

## 客户端导航的往返开销

在首次服务端渲染的页面加载时，孤岛是内联渲染的，不会有额外请求。但在**客户端导航**时，目标页面上的每个孤岛都必须从服务端获取（你可以在网络面板中看到这些请求）。这有真实的成本：

- 孤岛在导航期间会阻塞在一次网络往返上，除非你传入 `lazy` prop（并配合 `#fallback` 插槽）让它们以非阻塞方式渲染
- 一个每页面有许多孤岛的应用，每次导航都会发出许多请求

孤岛最适合通过整页加载到达的页面（内容页和营销页），或者每页面孤岛数量很少的场景。如果一个组件需要在客户端频繁更新，孤岛大概是不合适的工具。

当指向[仅服务端页面](/docs/directory-structure/app/pages#server-only-pages)的 `<NuxtLink>` 被预取时，它的孤岛响应也会被预取，因此往返发生在用户导航之前而不是导航期间。被预取的响应会按孤岛的 name、props 和 context 作为键缓存，而这正是孤岛挂载时使用的同一组键。预取失败并不致命：孤岛会在挂载时再次获取。

:::note
这适用于渲染整个 `.server.vue` 页面的那个孤岛。页面内部使用的孤岛仍然会在挂载时才被获取。
:::

## 预渲染与缓存

孤岛与静态渲染和缓存渲染配合得很好：

- 在预渲染期间（`nuxt generate` 或 `prerender` 路由规则），孤岛响应会被缓存，因此相同的孤岛（name、props 和 context 相同）只渲染一次并复用
- 由于 props 以 GET 查询参数传输，孤岛响应也可以由你的服务端或 CDN 在孤岛端点级别缓存
- 同一孤岛的两个实例若 props 相同，会共享一次服务端渲染和一条 payload 记录

请注意，孤岛响应仅以 name、props 和 context 作为键，正是这一点让它们独立于所在页面而可缓存；这也正是它们看不到当前路由的原因（见上文）。

如果你在构建一个近乎静态的网站，孤岛与 `prerender`、`noScripts` 路由规则结合起来效果很好。

:::read-more{to="/docs/guide/recipes/mostly-static-sites"}
参见近乎静态网站（mostly-static sites）配方，了解如何把预渲染、`noScripts`、孤岛和延迟水合组合起来。
:::

有一个需要注意的相互影响：孤岛插槽和 `nuxt-client` 组件依赖一小段内联脚本，在水合之前把 teleport 的内容重定位到位。在由 [`noScripts`](/docs/guide/going-further/features#noscripts) 渲染的路由上，这段脚本会被省略，因此完全可交互的 `nuxt-client` 组件在那里不会水合。普通的静态孤岛不受影响。

## 当前限制

服务端组件是实验性的，一些粗糙之处在开放的 issue 中被跟踪：

- 仅服务端组件和孤岛组件的大部分特性（例如插槽和 `nuxt-client` 组件）只对单文件组件可用。
- 使用孤岛会显著增加构建时生成的 chunk 数量（[#34855](https://github.com/nuxt/nuxt/issues/34855)）。
- 在 webpack 和 Rspack 下，服务端组件插槽中作用域化的 `:slotted()` 样式可能失效，因为服务端构建和客户端构建可能生成不同的作用域 ID（[#31510](https://github.com/nuxt/nuxt/issues/31510)）。
- 模板 ref 无法从父级引用服务端组件内部的元素（[#31512](https://github.com/nuxt/nuxt/issues/31512)）。
- `inject`/`provide` 不会跨越孤岛边界，因此从页面注入到一个独立的服务端组件是无效的（[#22751](https://github.com/nuxt/nuxt/issues/22751)）。
- 通过自动生成的包装组件渲染的服务端组件不会暴露加载与错误事件；如果你需要它的 `error` 事件和 `refresh()` 方法，请直接使用 `<NuxtIsland>`（[#25744](https://github.com/nuxt/nuxt/issues/25744)）。
- [`useId`](https://vuejs.org/api/composition-api-helpers#useid) 在孤岛内有已知的限制；参见 [`<NuxtIsland>` 文档](/docs/api/components/nuxt-island#known-limitations)。
- 每一层嵌套的孤岛都会带来额外开销，因此在孤岛中嵌套孤岛时要小心。
