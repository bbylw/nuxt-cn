## 理解模块类型

**官方模块**是带有 `@nuxt/` 前缀（作用域）的模块（例如 [`@nuxt/content`](https://content.nuxt.com)）。它们由 Nuxt 团队积极制作并维护。就像框架本身一样，我们非常欢迎社区贡献来帮助把它们做得更好！

**社区模块**是带有 `@nuxtjs/` 前缀（作用域）的模块（例如 [`@nuxtjs/tailwindcss`](https://tailwindcss.nuxtjs.org)）。它们是由社区成员制作并维护的、经过验证的模块。同样，我们欢迎任何人的贡献。

**第三方和其它社区模块**是（通常）带有 `nuxt-` 前缀的模块。任何人都可以制作它们，使用此前缀可以让这些模块在 npm 上被发现。这是起草和尝试一个想法的最佳起点！

**私有或个人模块**是为你自己的用例或公司制作的模块。它们无需遵循任何命名规则即可与 Nuxt 协同工作，通常可以在某个 npm 组织下看到作用域（例如 `@my-company/nuxt-auth`）。

## 列出你的模块

任何社区模块都欢迎被列在[模块列表](/modules) 上。要被列入，请在 [nuxt/modules](https://github.com/nuxt/modules/issues/new?template=module_request.yml) 仓库中提交 issue。Nuxt 团队可以在列出之前帮助你应用最佳实践。

## 加入 `nuxt-modules`

通过将你的模块迁移到 [nuxt-modules](https://github.com/nuxt-modules)，总有其他人可以提供帮助，这样我们就可以集中力量打造一个完美的解决方案。

如果你已经有一个已发布且可用的模块，并想将它转移到 `nuxt-modules`，请在 [nuxt/modules](https://github.com/nuxt/modules/issues/new) 提交 issue。

通过加入 `nuxt-modules`，我们可以在你的社区模块名前加上 `@nuxtjs/` 作用域，并为其文档提供一个子域名（例如 `my-module.nuxtjs.org`）。
