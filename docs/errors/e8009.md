# E8009

当某个路由使用流式传输时，等到页面错误抛出，响应已经开始写入浏览器。此时 Nuxt 无法切换为一个全新的错误响应，因此它会以一个客户端可以恢复的状态结束这个流：设置 `payload.error`，刷出 payload 脚本和剩余的 head 标签，并关闭文档，让浏览器在水合期间渲染 `error.vue`。

当这个恢复过程本身失败时，会报告此诊断信息：在 HTML 外壳之后注册的 head 标签，或结尾标签，无法被渲染。这样浏览器收到的就是空白页面或部分渲染的页面，而不是你的错误页面。

## 解决方法

首先修复最初的页面错误。只有当渲染抛出异常时才会走这条恢复路径，因此一旦页面能够正常渲染，这个诊断信息就会消失。

如果底层的错误是预期之内的（例如可能失败的上游请求），请在页面中处理它，而不是让它到达渲染器，这样就可以在流被提交之前发送一个正确的错误响应：

```vue [app/pages/blog.vue]
<script setup lang="ts">
const { data, error } = await useFetch('/api/content')

if (error.value) {
  throw createError({ statusCode: 404, statusMessage: 'Not found', fatal: true })
}
</script>
```

你也可以让该路由退出流式传输，这样错误会作为普通错误响应渲染，而不是在流中途进行恢复：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/blog/**': { streaming: false },
  },
})
```

如果页面错误已经修复但仍在报告此问题，说明失败发生在 head 渲染内部。请检查那些在应用处于错误状态时可能读取到不存在状态的 `useHead` 标签取值函数，并连同诊断信息中显示的 cause 一起报告该问题。
