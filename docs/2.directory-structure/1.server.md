Nuxt 会自动扫描这些目录中的文件，注册带热模块替换（HMR）支持的 API 和服务端处理器。

```bash [Directory Structure]
-| server/
---| api/
-----| hello.ts      # /api/hello
---| routes/
-----| bonjour.ts    # /bonjour
---| middleware/
-----| log.ts        # 记录所有请求
```

每个文件都应导出一个用 `defineHandler()` 定义的默认函数（`defineEventHandler()` 是它的别名）。

处理器可以直接返回 JSON 数据、`Promise` 或 `Response` 对象。

:::important
不要在你的服务端路由或工具函数中导入 Vue 应用代码（组件、组合式函数或其他仅限应用的工具函数），也不要在应用中导入仅限服务端的代码。
:::

:read-more{to="/docs/directory-structure/shared#why-you-cannot-mix-vue-and-nitro-code" title="为什么不能混用 Vue 和 Nitro 代码"}

```ts twoslash [server/api/hello.ts]
import { defineHandler } from 'nuxt/server'

export default defineHandler((event) => {
  return {
    hello: 'world',
  }
})
```

:::read-more{to="/docs/guide/going-further/server-imports"}
`nuxt/server` 是服务端工具函数的导入入口，也是服务端自动导入所解析到的模块。它不绑定于某个特定的 h3 或 Nitro 版本。
:::

你现在可以在页面和组件中通用地调用这个 API：

```vue [app/pages/index.vue]
<script setup lang="ts">
const { data } = await useFetch('/api/hello')
</script>

<template>
  <pre>{{ data }}</pre>
</template>
```

## 服务端路由（Server Routes）

`~~/server/api` 中的文件在其路由中会自动添加 `/api` 前缀。

:video-accordion{title="观看 Vue School 关于 API 路由的视频" videoId="761468863" platform="vimeo"}

要添加不带 `/api` 前缀的服务端路由，请将它们放入 `~~/server/routes` 目录。

**示例：**

```ts [server/routes/hello.ts]
import { defineHandler } from 'nuxt/server'

export default defineHandler(() => 'Hello World!')
```

以上例来说，`/hello` 路由可通过 <http://localhost:3000/hello> 访问。

:::note
请注意，目前服务端路由不像[页面](/docs/directory-structure/app/pages#dynamic-routes)那样支持动态路由的全部功能。
:::

## 服务端中间件（Server Middleware）

Nuxt 会自动读取 `~~/server/middleware` 中的任何文件，为你的项目创建服务端中间件。

中间件处理器会在任何其它服务端路由之前对每个请求运行，用于添加或检查请求头、记录请求日志，或扩展事件的请求对象。

:::note
中间件处理器不应返回任何内容（也不应关闭或响应请求），只能检查或扩展请求上下文，或抛出错误。
:::

**示例：**

```ts [server/middleware/log.ts]
import { defineHandler, getRequestURL } from 'nuxt/server'

export default defineHandler((event) => {
  console.log('New request: ' + getRequestURL(event))
})
```

```ts [server/middleware/auth.ts]
import { defineHandler } from 'nuxt/server'

export default defineHandler((event) => {
  event.context.auth = { user: 123 }
})
```

## 服务端插件（Server Plugins）

Nuxt 会自动读取 `~~/server/plugins` 目录中的任何文件，并将它们注册为 Nitro 插件。这允许扩展 Nitro 的运行时行为并钩入生命周期事件。

**示例：**

```ts [server/plugins/nitroPlugin.ts]
import { definePlugin } from 'nitro'

export default definePlugin((nitroApp) => {
  console.log('Nitro plugin', nitroApp)
})
```

:read-more{to="https://nitro.build/guide/plugins" title="Nitro 插件" target="_blank"}

## 服务端工具函数（Server Utilities）

服务端路由由 [h3js/h3](https://github.com/h3js/h3) 驱动，它提供了一组实用的辅助函数。

:read-more{to="https://www.jsdocs.io/package/h3#package-index-functions" title="可用的 H3 请求辅助函数" target="_blank"}

你可以在 `~~/server/utils` 目录中自行添加更多辅助函数。只有直接位于 `~~/server/utils` 中的文件会被自动导入；若要自动导入子目录中的辅助函数，请把它重新导出（re-export）到顶层文件中。

例如，你可以定义一个自定义的处理器工具函数，它包裹原始处理器，并在返回最终响应前执行额外的操作。

**示例：**

```ts [server/utils/handler.ts]
import { defineHandler } from 'nuxt/server'
import type { EventHandler } from 'nuxt/server'

export const defineWrappedResponseHandler = <Result> (handler: EventHandler<Result>) =>
  defineHandler(async (event) => {
    try {
      // 在路由处理器之前执行某些操作
      const response = await handler(event)
      // 在路由处理器之后执行某些操作
      return { response }
    } catch (err) {
      // 错误处理
      return { err }
    }
  })
```

```ts [server/api/hello.get.ts]
export default defineWrappedResponseHandler(event => 'hello world')
```

## 服务端别名 :badge[v4.3]{color="info" size="xs" class="align-middle"}

你可以使用 `#server` 别名从 `server/` 目录中的任意位置导入文件，无论导入文件位于何处。

```ts [server/api/users/[id]/profile.ts]
// 而不是像这样使用相对路径：
// import { formatUser } from '../../../utils/formatUser'

// 使用 #server 别名：
import { formatUser } from '#server/utils/formatUser'
```

此别名可确保服务端代码中的导入保持一致，在深层嵌套的路由处理器中尤其有用。

:::note
`#server` 别名只能在 `server/` 目录内使用。在客户端代码中使用 `#server` 导入会导致错误。
:::

## 服务端类型（Server Types）

`server/` 目录的自动导入和其他类型与应用（app）目录不同，因为它运行在与 `app/` 目录不同的上下文中。

默认情况下，Nuxt 4 会生成一个 [`tsconfig.json`](/docs/directory-structure/tsconfig)，其中包含一个覆盖 `server/` 文件夹的项目引用，以确保类型准确。

放在 `~~/server/types/` 中的类型只在服务端上下文中自动导入，因此你可以在服务端路由、中间件、插件和工具函数中引用它们，而无需导入。如果某些类型在 Vue 应用中同样需要，请把它们放在 [`shared/types/`](/docs/directory-structure/shared) 中。

```ts twoslash [server/types/todo.ts]
export interface Todo {
  id: string
  title: string
  completed: boolean
}
```

```ts [server/api/todos.get.ts]
import { defineHandler } from 'nuxt/server'

export default defineHandler((): Todo[] => {
  return []
})
```

只有直接位于 `server/types/` 中的文件会被扫描；嵌套子目录中的文件不会被自动导入，这与 [`shared/types/`](/docs/directory-structure/shared#how-files-are-scanned) 的行为一致。

## 配方（Recipes）

### 路由参数

服务端路由可以像 `/api/hello/[name].ts` 这样在文件名中使用方括号内的动态参数，并通过 `event.context.params` 访问。

```ts [server/api/hello/[name\\].ts]
import { defineHandler, getRouterParam } from 'nuxt/server'

export default defineHandler((event) => {
  const name = getRouterParam(event, 'name')

  return `Hello, ${name}!`
})
```

:::tip{to="https://h3.dev/examples/validate-data#validate-params"}
或者，使用 `getValidatedRouterParams` 配合 Zod 或 Valibot 之类的 schema 校验器，以获得运行时和类型安全。
:::

你现在可以通用地调用 `/api/hello/nuxt` 这个 API，并得到 `Hello, nuxt!`。

### 匹配 HTTP 方法

处理文件名可以添加 `.get`、`.post`、`.put`、`.delete` 等后缀，以匹配请求的 [HTTP 方法](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Methods)。

```ts [server/api/test.get.ts]
import { defineHandler } from 'nuxt/server'

export default defineHandler(() => 'Test get handler')
```

```ts [server/api/test.post.ts]
import { defineHandler } from 'nuxt/server'

export default defineHandler(() => 'Test post handler')
```

以上例来说，向 `/test` 发起：

- **GET** 方法：返回 `Test get handler`
- **POST** 方法：返回 `Test post handler`
- 任何其它方法：返回 405 错误

你也可以在目录内使用 `index.[method].ts`，以不同的方式组织代码，这对于创建 API 命名空间很有用。

:::code-group
```ts [server/api/foo/index.get.ts]
import { defineHandler } from 'nuxt/server'

export default defineHandler((event) => {
  // 处理 `api/foo` 端点的 GET 请求
})
```
```ts [server/api/foo/index.post.ts]
import { defineHandler } from 'nuxt/server'

export default defineHandler((event) => {
  // 处理 `api/foo` 端点的 POST 请求
})
```
```ts [server/api/foo/bar.get.ts]
import { defineHandler } from 'nuxt/server'

export default defineHandler((event) => {
  // 处理 `api/foo/bar` 端点的 GET 请求
})
```
:::

### 全捕获路由（Catch-all Route）

全捕获路由有助于处理回退路由。

例如，创建一个名为 `~~/server/api/foo/[...].ts` 的文件，将会为所有未匹配到任何路由处理器的请求（如 `/api/foo/bar/baz`）注册一个全捕获路由。

```ts [server/api/foo/[...\\].ts]
import { defineHandler } from 'nuxt/server'

export default defineHandler((event) => {
  // event.context.path 获取路由路径：'/api/foo/bar/baz'
  // event.context.params._ 获取路由片段：'bar/baz'
  return `Default foo handler`
})
```

你可以通过使用 `~~/server/api/foo/[...slug].ts` 为全捕获路由设置一个名称，并通过 `event.context.params.slug` 访问它。

```ts [server/api/foo/[...slug\\].ts]
import { defineHandler } from 'nuxt/server'

export default defineHandler((event) => {
  // event.context.params.slug 获取路由片段：'bar/baz'
  return `Default foo handler`
})
```

### 请求体处理（Body Handling）

```ts [server/api/submit.post.ts]
import { defineHandler, readBody } from 'nuxt/server'

export default defineHandler(async (event) => {
  const body = await readBody(event)
  return { body }
})
```

:::tip{to="https://unjs.io/blog/2023-08-15-h3-towards-the-edge-of-the-web/#runtime-type-safe-request-utils"}
或者，使用 `readValidatedBody` 配合 Zod 或 Valibot 之类的 schema 校验器，以获得运行时和类型安全。
:::

你现在可以通用地调用这个 API：

```vue [app/app.vue]
<script setup lang="ts">
async function submit () {
  const { body } = await $fetch('/api/submit', {
    method: 'post',
    body: { test: 123 },
  })
}
</script>
```

:::note
我们在文件名中使用 `submit.post.ts` 只是为了匹配能接收请求体的 `POST` 方法请求。在 GET 请求中使用 `readBody` 时，`readBody` 会抛出 `405 Method Not Allowed` HTTP 错误。
:::

### 查询参数（Query Parameters）

示例查询 `/api/query?foo=bar&baz=qux`

```ts [server/api/query.get.ts]
import { defineHandler, getQuery } from 'nuxt/server'

export default defineHandler((event) => {
  const query = getQuery(event)

  return { a: query.foo, b: query.baz }
})
```

:::tip{to="https://unjs.io/blog/2023-08-15-h3-towards-the-edge-of-the-web#runtime-type-safe-request-utils"}
或者，使用 `getValidatedQuery` 配合 Zod 或 Valibot 之类的 schema 校验器，以获得运行时和类型安全。
:::

### 错误处理

如果不抛出任何错误，将返回状态码 `200 OK`。

任何未捕获的错误都会返回 `500 Internal Server Error` HTTP 错误。

要返回其它错误码，请使用 [`createError`](/docs/api/utils/create-error) 抛出异常：

```ts [server/api/validation/[id\\].ts]
import { createError, defineHandler, getRouterParam } from 'nuxt/server'

export default defineHandler((event) => {
  const id = Number(getRouterParam(event, 'id'))

  if (!Number.isInteger(id)) {
    throw createError({
      status: 400,
      statusText: 'ID should be an integer',
    })
  }
  return 'All good'
})
```

### 状态码

要返回其它状态码，请使用 [`setResponseStatus`](/docs/api/utils/set-response-status) 工具函数。

例如，返回 `202 Accepted`：

```ts [server/api/validation/[id\\].ts]
import { defineHandler, setResponseStatus } from 'nuxt/server'

export default defineHandler((event) => {
  setResponseStatus(event, 202)
})
```

### 请求 Cookie

```ts [server/api/cookies.ts]
import { defineHandler, parseCookies } from 'nuxt/server'

export default defineHandler((event) => {
  const cookies = parseCookies(event)

  return { cookies }
```

### 转发请求头

默认情况下，在服务端路由中发起 fetch 请求时，不会转发传入请求的请求头。你可以使用 `serverFetch` 调用你应用的某个路由，并转发传入请求的 `cookie` 和 `authorization` 请求头。

```ts [server/api/forward.ts]
import { defineHandler, serverFetch } from 'nuxt/server'

export default defineHandler((event) => {
  return serverFetch(event, '/api/forwarded')
})
```

传入 `forwardHeaders` 并给出一组请求头名称可以转发另一套请求头，传入 `false` 则一个都不转发：

```ts
serverFetch(event, '/api/forwarded', { forwardHeaders: ['cookie', 'x-tenant'] })
```

### 响应后等待 Promise（Awaiting Promises After Response）

在处理服务端请求时，你可能需要执行一些不应阻塞对客户端的响应（例如缓存和日志记录）的异步任务。你可以使用 `event.waitUntil` 在后台等待一个 Promise，而不会延迟响应。

`event.waitUntil` 方法接受一个 Promise，该 Promise 会在处理器终止前被等待，确保任务得以完成——即使服务端原本会在响应发送后立即终止处理器。它与运行时平台集成，以利用其在响应发送后处理异步操作的原生能力。

```ts [server/api/background-task.ts]
import { defineHandler } from 'nitro/h3'

const timeConsumingBackgroundTask = async () => {
  await new Promise(resolve => setTimeout(resolve, 1000))
}

export default defineHandler((event) => {
  // 安排一个后台任务，但不阻塞响应
  event.waitUntil(timeConsumingBackgroundTask())

  // 立即向客户端发送响应
  return 'done'
})
```

## 高级用法

### Nitro 配置

你可以使用 `nuxt.config` 中的 `nitro` 键来直接设置 [Nitro 配置](https://nitro.build/config)。

:::warning
这是一个高级选项。自定义配置可能会影响生产部署，因为当 Nitro 在 Nuxt 的 semver 次版本中升级时，配置接口可能会发生变化。
:::

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // https://nitro.build/config
  nitro: {},
})
```

:read-more{to="/docs/guide/concepts/server-engine"}

### Nitro 构建器

Nitro 默认使用 [Rolldown](https://rolldown.rs) 打包你的服务端。使用 webpack 或 Rspack 应用构建器时，你可以通过 `nitro.builder`（或环境变量 `NITRO_BUILDER`）选择其他 [Nitro 构建器](https://nitro.build/config/build#builder)。例如，要用 [Rspack](https://rspack.rs) 同时构建你的应用和服务端：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  builder: 'rspack',
  nitro: {
    builder: 'rspack',
  },
})
```

你不需要自己安装 `@rspack/core`：Nitro 的 `rspack` 构建器使用的是随 `@nuxt/rspack-builder` 一起安装的那个。

:::warning
Nitro 的 `rspack` 和 `bun` 构建器仍是实验性的。启用 `experimental.nitroViteEnvironment` 时，由 Vite 构建服务端，`nitro.builder` 会被忽略。
:::

### 嵌套路由（Nested Router）

```ts [server/api/hello/[...slug\\].ts]
import { createRouter, defineEventHandler, useBase } from 'h3'

const router = createRouter()

router.get('/test', defineEventHandler(() => 'Hello World'))

export default useBase('/api/hello', router.handler)
```

### 发送流（Sending Streams）

:::tip
这是一个实验性功能，在所有环境中均可用。
:::

你可以从事件处理器中直接返回流。

```ts [server/api/foo.get.ts]
import fs from 'node:fs'
import { defineHandler } from 'nuxt/server'

export default defineHandler(() => {
  return fs.createReadStream('/path/to/file')
})
```

### 发送重定向（Sending Redirect）

```ts [server/api/foo.get.ts]
import { defineHandler, sendRedirect } from 'nuxt/server'

export default defineHandler((event) => {
  return sendRedirect(event, '/path/redirect/to', 302)
})
```

### 旧式处理器或中间件（Legacy Handler or Middleware）

```ts [server/api/legacy.ts]
import { fromNodeHandler } from 'nitro/h3'

export default fromNodeHandler((req, res) => {
  res.end('Legacy handler')
})
```

:::important
可以使用 [h3js/h3](https://github.com/h3js/h3) 提供旧式支持，但建议尽可能避免使用旧式处理器。它们需要 Node.js 的 request 和 response，因此在非 Node 的部署预设（preset）以及进程内请求（例如服务端渲染期间用 `serverFetch` 或 `$fetch` 请求你自己的路由）中会失败。
:::

```ts [server/middleware/legacy.ts]
import { fromNodeHandler } from 'nitro/h3'

export default fromNodeHandler((req, res, next) => {
  console.log('Legacy middleware')
  next()
})
```

:::warning
切勿将 `next()` 回调与 `async` 或返回 `Promise` 的旧式中间件结合使用。
:::

### 服务端存储（Server Storage）

Nitro 提供了一个跨平台的 [KV 存储层](https://nitro.build/docs/storage)。要配置额外的存储挂载点，你可以使用 `nitro.kv`，或[服务端插件](/docs/directory-structure/server#server-plugins)。

**添加 Redis 存储的示例：**

使用 `nitro.kv`：

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    kv: {
      redis: {
        driver: 'redis',
        /* redis 连接器选项 */
        port: 6379, // Redis 端口
        host: '127.0.0.1', // Redis 主机
        username: '', // 需要 Redis >= 6
        password: '',
        db: 0, // 默认为 0
        tls: {}, // tls/ssl
      },
    },
  },
})
```

然后在你的 API 处理器中：

```ts [server/api/storage/test.ts]
import { useKV } from 'nitro/kv'
import { defineHandler } from 'nuxt/server'

export default defineHandler(async (event) => {
  // 列出所有键
  const keys = await useKV('redis').getKeys()

  // 设置一个键
  await useKV('redis').setItem('foo', 'bar')

  // 移除一个键
  await useKV('redis').removeItem('foo')

  return {}
})
```

:::read-more{to="https://nitro.build/docs/storage" target="_blank"}
阅读更多关于 Nitro KV 存储的内容。
:::

或者，你也可以使用服务端插件和运行时配置来创建一个存储挂载点：

:::code-group
```ts [server/plugins/storage.ts]
import { definePlugin } from 'nitro'
import { useKV } from 'nitro/kv'
import redisDriver from 'unstorage/drivers/redis'
import { useRuntimeConfig } from 'nuxt/server'

export default definePlugin(() => {
  const storage = useKV()

  // 从运行时配置或其他来源动态传入凭据
  const driver = redisDriver({
    base: 'redis',
    host: useRuntimeConfig().redis.host,
    port: useRuntimeConfig().redis.port,
    /* 其他 redis 连接器选项 */
  })

  // 挂载驱动
  storage.mount('redis', driver)
})
```

``` ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    redis: { // 默认值
      host: '',
      port: 0,
      /* 其他 redis 连接器选项 */
    },
  },
})
```
:::
