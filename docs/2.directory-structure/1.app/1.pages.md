:::note
为了减少应用的打包体积，此目录是**可选的**，意味着如果你只使用 [`app.vue`](/docs/directory-structure/app/app)，则不会包含 [`vue-router`](https://router.vuejs.org)。要强制启用页面系统，请在 `nuxt.config` 中设置 `pages: true`，或拥有一个 [`router.options.ts`](/docs/guide/recipes/custom-routing#using-routeroptions)。
:::

## 用法

页面是 Vue 组件，可以使用 Nuxt 支持的任何[有效扩展名](/docs/api/nuxt-config#extensions)（默认是 `.vue`、`.js`、`.jsx`、`.mjs`、`.ts` 或 `.tsx`）。

Nuxt 会为 `~/pages/` 目录中的每个页面自动创建一个路由。

:::tip
只有在你没有禁用 `nitro.prerender.crawlLinks`、且你的 `nitro.prerender.routes` 列表中至少有一个页面时，页面才会被自动注册进行预渲染。参见[预渲染指南](/docs/getting-started/prerendering)。
:::

:::code-group

```vue [app/pages/index.vue]
<template>
  <h1>Index page</h1>
</template>
```

```ts twoslash [pages/index.ts]
// https://vuejs.org/guide/extras/render-function.html
export default defineComponent({
  render () {
    return h('h1', 'Index page')
  },
})
```

```tsx twoslash [pages/index.tsx]
// https://nuxt.com/docs/examples/advanced/jsx
// https://vuejs.org/guide/extras/render-function.html#jsx-tsx
export default defineComponent({
  render () {
    return <h1>Index page</h1>
  },
})
```

:::

`app/pages/index.vue` 文件会被映射到应用的 `/` 路由。

如果你使用了 [`app.vue`](/docs/directory-structure/app/app)，请确保使用 [`<NuxtPage/>`](/docs/api/components/nuxt-page) 组件来显示当前页面：

```vue [app/app.vue]
<template>
  <div>
    <!-- 所有页面共享的标记，例如 NavBar -->
    <NuxtPage />
  </div>
</template>
```

页面**必须只有一个根元素**，以便在页面之间应用[路由过渡](/docs/getting-started/transitions)。HTML 注释也被视为元素。

这意味着当路由被服务端渲染或静态生成时，你能正确看到其内容；但在客户端导航到该路由时，路由之间的过渡会失败，你会看到该路由未被渲染。

以下是一些示例，说明只包含单个根元素的页面是什么样子：

:::code-group

```vue [app/pages/working.vue]
<template>
  <div>
    <!-- 这个页面正确地只有一个根元素 -->
    Page content
  </div>
</template>
```

```vue [app/pages/bad-1.vue]
<template>
  <!-- 这个页面在客户端导航期间路由改变时不会渲染，因为这个注释 -->
  <div>Page content</div>
</template>
```

```vue [app/pages/bad-2.vue]
<template>
  <div>This page</div>
  <div>Has more than one root element</div>
  <div>并且在客户端导航期间路由改变时不会渲染</div>
</template>
```

:::

## 动态路由

如果你将任何内容放在方括号中，它会被转换为[动态路由](https://router.vuejs.org/guide/essentials/dynamic-matching)参数。你可以在文件名或目录中混合搭配多个参数，甚至是静态文本。

如果你想让某个参数变为_可选的_，必须用双方括号将其括起来——例如，`~/pages/[[slug]]/index.vue` 或 `~/pages/[[slug]].vue` 会同时匹配 `/` 和 `/test`。

```bash [Directory Structure]
-| pages/
---| index.vue
---| users-[group]/
-----| [id].vue
```

给定上面的示例，你可以在组件中通过 `$route` 对象访问 group/id：

```vue [app/pages/users-[group\\]/[id\\].vue]
<template>
  <p>{{ $route.params.group }} - {{ $route.params.id }}</p>
</template>
```

导航到 `/users-admins/123` 会渲染：

```html
<p>admins - 123</p>
```

如果你想使用 Composition API 访问路由，有一个全局的 [`useRoute`](/docs/api/composables/use-route) 函数，可以让你像 Options API 中的 `this.$route` 那样访问路由。

```vue twoslash
<script setup lang="ts">
const route = useRoute()

if (route.params.group === 'admins' && !route.params.id) {
  console.log('警告！请确保用户已通过认证！')
}
</script>
```

:::note
具名的父路由会优先于嵌套的动态路由。对于 `/foo/hello` 路由，`~/pages/foo.vue` 会优先于 `~/pages/foo/[slug].vue`。:br 使用 `~/pages/foo/index.vue` 和 `~/pages/foo/[slug].vue` 可以用不同的页面匹配 `/foo` 和 `/foo/hello`。
:::

## 全捕获路由

如果你需要一个全捕获路由，可以用 `[...slug].vue` 这样的文件名来创建。这会匹配该路径下的_所有_路由。

```vue [app/pages/[...slug\\].vue]
<template>
  <p>{{ $route.params.slug }}</p>
</template>
```

导航到 `/hello/world` 会渲染：

```html
<p>["hello", "world"]</p>
```

## 嵌套路由

可以使用 `<NuxtPage>` 来显示[嵌套路由](https://router.vuejs.org/guide/essentials/nested-routes)。

示例：

```bash [Directory Structure]
-| pages/
---| parent/
-----| child.vue
---| parent.vue
```

这个文件树会生成以下路由：

```js
[
  {
    path: '/parent',
    component: '~/pages/parent.vue',
    name: 'parent',
    children: [
      {
        path: 'child',
        component: '~/pages/parent/child.vue',
        name: 'parent-child',
      },
    ],
  },
]
```

要显示 `child.vue` 组件，你必须在 `app/pages/parent.vue` 中插入 `<NuxtPage>` 组件：

```vue {}[pages/parent.vue]
<template>
  <div>
    <h1>我是父视图</h1>
    <NuxtPage :foobar="123" />
  </div>
</template>
```

```vue {}[pages/parent/child.vue]
<script setup lang="ts">
const props = defineProps({
  foobar: String,
})

console.log(props.foobar)
</script>
```

### 子路由键

如果你想要更精细地控制 `<NuxtPage>` 组件何时重新渲染（例如为了过渡），你可以通过 `pageKey` 属性传入字符串或函数，也可以通过 `definePageMeta` 定义 `key` 值：

```vue {}[pages/parent.vue]
<template>
  <div>
    <h1>我是父视图</h1>
    <NuxtPage :page-key="route => route.fullPath" />
  </div>
</template>
```

或者：

```vue twoslash {}[pages/parent/child.vue]
<script setup lang="ts">
definePageMeta({
  key: route => route.fullPath,
})
</script>
```

## 命名视图 :badge[v4.5]{color="info" size="xs" class="align-middle"}

单个路由可以通过将每个出口命名为 `name`，并为每个名称提供同级的页面文件，从而渲染到父组件中的多个 `<NuxtPage>` 出口。

使用 `name@view.vue` 文件名约定，在默认路由文件旁边声明一个命名视图：

```bash [Directory Structure]
-| pages/
---| parent/
-----| child.vue
-----| child@sidebar.vue
---| parent.vue
```

然后从父组件按名称渲染每个出口：

```vue [pages/parent.vue]
<template>
  <div>
    <NuxtPage />
    <aside>
      <NuxtPage name="sidebar" />
    </aside>
  </div>
</template>
```

当用户导航到 `/parent/child` 时，`child.vue` 会渲染到默认的 `<NuxtPage />`，而 `child@sidebar.vue` 会渲染到 `<NuxtPage name="sidebar" />`。没有匹配命名视图的出口会留空。

:::note
`definePageMeta` 只从默认路由文件读取。在 `name@view.vue` 同级文件中声明的 meta 对该路由没有影响。
:::

::read-more{title="命名视图" to="https://router.vuejs.org/guide/essentials/named-views.html" target="_blank"}

## 路由分组

在某些情况下，你可能希望将一组路由进行分组，而不影响基于文件的路由。为此，你可以将文件放在用括号 `(` 和 `)` 包裹的文件夹中。

例如：

```bash [Directory structure]
-| pages/
---| index.vue
---| (marketing)/
-----| about.vue
-----| contact.vue
```

这会在你的应用中生成 `/`、`/about` 和 `/contact` 页面。就你的 URL 结构而言，`marketing` 分组会被忽略。

### 访问路由分组 :badge[v4.3]{color="info" size="xs" class="align-middle"}

路由分组会通过 `route.meta.groups` 自动在路由元数据中可用。
这让你可以在组件中为条件逻辑、样式或其他目的访问分组信息。

```vue {}[pages/(marketing)/about.vue]
<script setup lang="ts">
const route = useRoute()

console.log(route.meta.groups) // 输出：['marketing']
</script>

<template>
  <div>
    <p v-if="route.meta.groups?.includes('marketing')">
      这是一个营销页面
    </p>
  </div>
</template>
```

## 页面元数据

你可能想为应用中的每个路由定义元数据。你可以使用 `definePageMeta` 宏来做到这一点，它在 `<script>` 和 `<script setup>` 中都能工作：

```vue twoslash
<script setup lang="ts">
definePageMeta({
  title: '我的主页',
})
</script>
```

然后这些数据可以从你应用的其他地方通过 `route.meta` 对象访问。

```vue twoslash
<script setup lang="ts">
const route = useRoute()

console.log(route.meta.title) // 我的主页
</script>
```

如果你使用的是嵌套路由，来自所有这些路由的页面元数据会被合并到一个对象中。关于路由 meta 的更多内容，请参阅 [vue-router 文档](https://router.vuejs.org/guide/advanced/meta)。

与 `defineEmits` 或 `defineProps` 很像（参见 [Vue 文档](https://vuejs.org/api/sfc-script-setup#defineprops-defineemits)），`definePageMeta` 是一个**编译器宏**。它会被编译掉，因此你无法在组件内部引用它。相反，传递给它的元数据会被提升到组件之外。
因此，页面 meta 对象不能引用组件。不过，它可以引用导入的绑定，以及本地定义的**纯函数**。

:::warning
确保不要引用任何响应式数据或会产生副作用的函数。这可能导致意外行为。
:::

```vue
<script setup lang="ts">
import { someData } from '~/utils/example'

function validateIdParam (route) {
  return route.params.id && !Number.isNaN(Number(route.params.id))
}

const title = ref('')

definePageMeta({
  validate: validateIdParam,
  someData,
  title, // 不要这样做，ref 会被提升到组件之外
})
</script>
```

### 特殊元数据

当然，欢迎你为整个应用定义自己使用的元数据。但使用 `definePageMeta` 定义的一些元数据有特定用途：

#### `alias`

你可以定义页面别名。别名允许你从不同路径访问同一页面。它可以是字符串，也可以是[vue-router 文档](https://router.vuejs.org/guide/essentials/redirect-and-alias#Alias)中定义的字符串数组。

#### `keepalive`

如果你在 `definePageMeta` 中设置 `keepalive: true`，Nuxt 会自动用 [Vue 的 `<KeepAlive>` 组件](https://vuejs.org/guide/built-ins/keep-alive#keepalive)包裹你的页面。例如，在拥有动态子路由的父路由中，如果你想在路由改变时保留页面状态，这可能很有用。

当你的目标是为父路由保留状态时，请使用此语法：`<NuxtPage keepalive />`。你也可以设置要传递给 `<KeepAlive>` 的 props（参见[完整列表](https://vuejs.org/api/built-in-components#keepalive)）。

你可以在[你的 `nuxt.config`](/docs/api/nuxt-config#keepalive) 中为此属性设置默认值。

#### `key`

[见上文](/docs/directory-structure/app/pages#child-route-keys)。

#### `layout`

你可以定义用于渲染路由的布局。可以是 `false`（禁用任何布局）、字符串，或者 ref/computed（如果你想让它以某种方式变为响应式）。[关于布局的更多内容](/docs/directory-structure/app/layouts)。

#### `layoutTransition` 和 `pageTransition`

你可以为包裹你的页面和布局的 `<transition>` 组件定义过渡属性，或传入 `false` 以禁用该路由的 `<transition>` 包裹。你可以查看[可传递的选项列表](https://vuejs.org/api/built-in-components#transition)，或阅读[关于过渡如何工作的更多内容](https://vuejs.org/guide/built-ins/transition#transition)。

你可以在[你的 `nuxt.config`](/docs/api/nuxt-config#layouttransition) 中为此类属性设置默认值。

#### `middleware`

你可以定义在加载此页面之前应用的中间件。它会与所有其他在匹配的父/子路由中使用的中间件合并。它可以是字符串、函数（遵循[全局前置守卫模式](https://router.vuejs.org/guide/advanced/navigation-guards#Global-Before-Guards)的匿名/内联中间件函数），或字符串/函数数组。[关于具名中间件的更多内容](/docs/directory-structure/app/middleware)。

#### `name`

你可以为此页面的路由定义一个名称。

#### `path`

如果你有比文件名能表达的更复杂的模式，可以定义路径匹配器。更多信息请参阅 [vue-router 文档](https://router.vuejs.org/guide/essentials/route-matching-syntax#Custom-regex-in-params)。

#### `props`

允许将路由 `params` 作为 props 传递给页面组件。更多信息请参阅 [vue-router 文档](https://router.vuejs.org/guide/essentials/passing-props)。

### 为自定义元数据添加类型

如果你为页面添加了自定义元数据，可能希望以一种类型安全的方式进行。可以扩展 `definePageMeta` 接受的对象的类型：

```ts [index.d.ts]
declare module '#app' {
  interface PageMeta {
    pageType?: string
  }
}

// 在扩展类型时，总是要确保导入/导出某些内容
export {}
```

## 导航

要在应用的页面之间导航，你应该使用 [`<NuxtLink>`](/docs/api/components/nuxt-link) 组件。

这个组件随 Nuxt 一同提供，因此你不需要像其他组件那样导入它。

一个简单的链接，指向 `app/pages` 文件夹中的 `index.vue` 页面：

```vue
<template>
  <NuxtLink to="/">Home page</NuxtLink>
</template>
```

:::read-more{to="/docs/api/components/nuxt-link"}
了解更多关于 `<NuxtLink>` 用法的信息。
:::

## 编程式导航

Nuxt 允许通过 `navigateTo()` 工具方法进行编程式导航。使用这个工具方法，你将能够在应用中以编程方式引导用户。这在接收用户输入并在应用中动态引导用户时非常有用。在此示例中，我们有一个名为 `navigate()` 的简单方法，会在用户提交搜索表单时被调用。

:::note
务必始终 `await` `navigateTo`，或者通过从函数返回其结果来链式调用它。
:::

```vue twoslash
<script setup lang="ts">
const name = ref('')
const type = ref(1)

function navigate () {
  return navigateTo({
    path: '/search',
    query: {
      name: name.value,
      type: type.value,
    },
  })
}
</script>
```

## 仅客户端页面

你可以通过添加 `.client.vue` 后缀将页面定义为[仅客户端](/docs/directory-structure/app/components#client-components)。此页面的内容都不会在服务端渲染。

## 仅服务端页面

你可以通过添加 `.server.vue` 后缀将页面定义为[仅服务端](/docs/directory-structure/app/components#server-components)。虽然你可以使用客户端导航（由 `vue-router` 控制）导航到该页面，但它会自动使用服务端组件渲染，意味着渲染该页面所需的代码不会包含在你的客户端包中。

:::warning
仅服务端页面必须只有一个根元素。（HTML 注释也被视为元素。）
:::

## 多个 Pages 目录

默认情况下，你所有的页面都应该放在项目根目录的一个 `app/pages` 目录中。

不过，你可以使用 [Nuxt Layers](/docs/getting-started/layers) 来创建应用页面分组：

```bash [Directory Structure]
-| some-app/
---| nuxt.config.ts
---| pages/
-----| app-page.vue
-| nuxt.config.ts
```

```ts twoslash [some-app/nuxt.config.ts]
// some-app/nuxt.config.ts
export default defineNuxtConfig({
})
```

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['./some-app'],
})
```
