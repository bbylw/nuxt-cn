Nuxt 提供了一个可定制的**路由中间件**框架，你可以在整个应用中使用它，非常适合提取那些希望在导航到特定路由之前运行的代码。

共有三种路由中间件：

1. 匿名（或内联）路由中间件，直接在页面内定义。
2. 具名路由中间件，放置在 `app/middleware/` 中，在页面中使用时通过异步导入自动加载。
3. 全局路由中间件，放置在 `app/middleware/` 中并带有 `.global` 后缀，会在每次路由改变时运行。

前两种路由中间件可以在 [`definePageMeta`](/docs/api/utils/define-page-meta) 中定义。

:::note
中间件的名称会被规范化为 kebab-case（短横线命名）：`myMiddleware` 会变成 `my-middleware`。
:::

:::note
只有位于目录顶层的文件（或任意子目录中的 index 文件）会被注册。index 文件以包含它的文件夹来命名：`middleware/auth/index.ts` 会被注册为 `auth`。
:::

:::note
路由中间件运行在你的 Nuxt 应用的 Vue 部分中。尽管名称相似，它与[服务端中间件](/docs/directory-structure/server#server-middleware)完全不同，后者运行在你应用的 Nitro 服务端部分。
:::

## 用法

路由中间件是导航守卫，接收当前路由和下一个路由作为参数。

```ts twoslash [middleware/my-middleware.ts]
export default defineNuxtRouteMiddleware((to, from) => {
  if (to.params.id === '1') {
    return abortNavigation()
  }
  // 在真实应用中，你可能不会将每个路由都重定向到 `/`
  // 不过在重定向前检查 `to.path` 很重要，否则
  // 你可能会陷入无限重定向循环
  if (to.path !== '/') {
    return navigateTo('/')
  }
})
```

Nuxt 提供了两个全局可用的辅助函数，可以直接从中间件中返回它们。

1. [`navigateTo`](/docs/api/utils/navigate-to) - 重定向到给定的路由
2. [`abortNavigation`](/docs/api/utils/abort-navigation) - 中止导航，并带有可选的错误信息。

与 `vue-router` 的[导航守卫](https://router.vuejs.org/guide/advanced/navigation-guards#Global-Before-Guards)不同，这里不会传入第三个 `next()` 参数，**重定向或取消路由导航是通过从中间件返回一个值来处理的**。

可能的返回值有：

* 什么也不返回（简单的 `return` 或完全不返回） - 不阻塞导航，会进入下一个中间件函数（如果有），或完成路由导航
* `return navigateTo('/')` - 重定向到给定路径，如果重定向发生在服务端，则将重定向码设为 [`302 Found`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/302)
* `return navigateTo('/', { redirectCode: 301 })` - 重定向到给定路径，如果重定向发生在服务端，则将重定向码设为 [`301 Moved Permanently`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/301)
* `return abortNavigation()` - 停止当前导航
* `return abortNavigation(error)` - 以错误拒绝当前导航

:read-more{to="/docs/api/utils/navigate-to"}
:read-more{to="/docs/api/utils/abort-navigation"}

:::important
我们建议使用上面的辅助函数来进行重定向或停止导航。[vue-router 文档](https://router.vuejs.org/guide/advanced/navigation-guards#Global-Before-Guards)中描述的其他可能返回值也许能用，但未来可能会有破坏性变更。
:::

## 中间件执行顺序

中间件按以下顺序运行：

1. 全局中间件
2. 页面定义的中间件顺序（如果使用数组语法声明了多个中间件）

例如，假设你有以下中间件和组件：

```bash [app/middleware/ 目录]
-| middleware/
---| analytics.global.ts
---| setup.global.ts
---| auth.ts
```

```vue twoslash [pages/profile.vue]
<script setup lang="ts">
definePageMeta({
  middleware: [
    function (to, from) {
      // 自定义内联中间件
    },
    'auth',
  ],
})
</script>
```

你可以预期中间件按以下顺序运行：

1. `analytics.global.ts`
2. `setup.global.ts`
3. 自定义内联中间件
4. `auth.ts`

### 全局中间件排序

默认情况下，全局中间件会基于文件名按字母顺序执行。

不过，有时你可能想定义特定的顺序。例如，在上面的场景中，`setup.global.ts` 可能需要在 `analytics.global.ts` 之前运行。在这种情况下，我们建议用「字母序」数字作为全局中间件的前缀。

```bash [Directory structure]
-| middleware/
---| 01.setup.global.ts
---| 02.analytics.global.ts
---| auth.ts
```

:::note
如果你还不熟悉「字母序」数字编号，请记住文件名是作为字符串排序的，而不是数值。例如，`10.new.global.ts` 会排在 `2.new.global.ts` 之前。这正是示例中给个位数前缀补 `0` 的原因。
:::

## 中间件何时运行

如果你的站点是服务端渲染或预生成的，初始页面的中间件既会在页面渲染时执行，也会在客户端再次执行。如果你的中间件需要浏览器环境（例如你有一个预生成的站点、激进地缓存响应，或者想从本地存储中读取某个值），就可能需要这样做。

不过，如果你想避免这种行为，可以这样做：

```ts twoslash [middleware/example.ts]
export default defineNuxtRouteMiddleware((to) => {
  // 跳过服务端的中间件
  if (import.meta.server) {
    return
  }
  // 完全跳过客户端中间件
  if (import.meta.client) {
    return
  }
  // 或只跳过初始客户端加载时的中间件
  const nuxtApp = useNuxtApp()
  if (import.meta.client && nuxtApp.isHydrating && nuxtApp.payload.serverRendered) {
    return
  }
})
```

即使你在服务端的中间件中抛出了错误、并渲染了错误页面，此规则也成立。中间件仍然会在浏览器中再次运行。

:::note
渲染错误页面是一次完全独立的页面加载，意味着任何已注册的中间件都会再次运行。你可以在中间件中使用 [`useError`](/docs/getting-started/error-handling#useerror) 来检查是否正在处理错误。
:::

## 在中间件中访问路由

始终在你的中间件中使用 `to` 和 `from` 参数来访问下一个和上一个路由。完全避免在此上下文中使用 [`useRoute()`](/docs/api/composables/use-route) 组合式函数。
在中间件中**没有「当前路由」的概念**，因为中间件可以中止导航或重定向到不同的路由。`useRoute()` 组合式函数在这个上下文中永远是不准确的。

:::warning
有时，你可能会调用一个内部使用了 `useRoute()` 的组合式函数，这会触发此警告，即使你的中间件中没有直接调用。
这会导致**与上面相同的问题**，因此你应该将函数结构改为接受路由作为参数，当它们在中间件中使用时。
:::

:::code-group
```ts twoslash [middleware/access-route.ts]
// @errors: 2304
export default defineNuxtRouteMiddleware((to) => {
  // 将路由作为参数传递给函数，避免在中间件中调用 `useRoute()`
  doSomethingWithRoute(to)

  // ❌ 这会输出警告，且不被推荐
  callsRouteInternally()
})
```

```ts twoslash [utils/handle-route.ts]
// 提供路由作为参数，以便在中间件中正确使用
export function doSomethingWithRoute (route = useRoute()) {
  // ...
}
```
```ts twoslash [utils/dont-do-this.ts]
// ❌ 此函数不适合在中间件中使用
export function callsRouteInternally () {
  const route = useRoute()
  // ...
}
```

:::

## 动态添加中间件

可以使用 [`addRouteMiddleware()`](/docs/api/utils/add-route-middleware) 辅助函数手动添加全局或具名路由中间件，例如从插件中添加。

```ts twoslash
export default defineNuxtPlugin(() => {
  addRouteMiddleware('global-test', () => {
    console.log('这个全局中间件是在插件中添加的，会在每次路由改变时运行')
  }, { global: true })

  addRouteMiddleware('named-test', () => {
    console.log('这个具名中间件是在插件中添加的，会覆盖任何同名的现有中间件')
  })
})
```

## 示例

```bash [Directory Structure]
-| middleware/
---| auth.ts
```

在你的页面文件中，你可以引用这个路由中间件：

```vue twoslash
<script setup lang="ts">
definePageMeta({
  middleware: ['auth'],
  // 或 middleware: 'auth'
})
</script>
```

现在，在导航到该页面完成之前，`auth` 路由中间件会先运行。

## 在构建时设置中间件

与使用每个页面上的 `definePageMeta` 不同，你可以在 `pages:extend` 钩子中添加具名路由中间件。

```ts twoslash [nuxt.config.ts]
import type { NuxtPage } from 'nuxt/schema'

export default defineNuxtConfig({
  hooks: {
    'pages:extend' (pages) {
      function setMiddleware (pages: NuxtPage[]) {
        for (const page of pages) {
          if (/* 某个条件 */ Math.random() > 0.5) {
            page.meta ||= {}
            // 注意这会覆盖页面中 `definePageMeta` 设置的任何中间件
            page.meta.middleware = ['named']
          }
          if (page.children) {
            setMiddleware(page.children)
          }
        }
      }
      setMiddleware(pages)
    },
  },
})
```
