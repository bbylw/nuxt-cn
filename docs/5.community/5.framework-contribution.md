阅读完[通用贡献指南](/docs/community/contribution)后，这里是关于向 [`nuxt/nuxt`](https://github.com/nuxt/nuxt) 仓库贡献的一些具体要点。

## Monorepo 指南

- `packages/kit`：用于编写 Nuxt 模块的工具包，发布为 [`@nuxt/kit`](https://www.npmjs.com/package/@nuxt/kit)。
- `packages/nitro-server`：Nuxt 默认的服务端构建器，基于 [Nitro](https://nitro.build)，发布为 [`@nuxt/nitro-server`](https://www.npmjs.com/package/@nuxt/nitro-server)。
- `packages/nuxt`：Nuxt 的核心，发布为 [`nuxt`](https://www.npmjs.com/package/nuxt)。
- `packages/schema`：跨版本的 Nuxt 类型定义和默认值，发布为 [`@nuxt/schema`](https://www.npmjs.com/package/@nuxt/schema)。
- `packages/ui-templates`：Nuxt 内置 HTML 模板（错误页面、加载页面、欢迎页面）的源码。
- `packages/rsbuild`：用于 Nuxt 的 [Rsbuild](https://rsbuild.rs) 打包器，发布为 [`@nuxt/rsbuild-builder`](https://www.npmjs.com/package/@nuxt/rsbuild-builder)。
- `packages/rspack`：用于 Nuxt 的、已弃用的 [Rspack](https://rspack.rs) 打包器（已由 `@nuxt/rsbuild-builder` 取代），发布为 [`@nuxt/rspack-builder`](https://www.npmjs.com/package/@nuxt/rspack-builder)。
- `packages/vite`：用于 Nuxt 的 [Vite](https://vite.dev) 打包器，发布为 [`@nuxt/vite-builder`](https://www.npmjs.com/package/@nuxt/vite-builder)。
- `packages/vite-server`：用于 Nuxt 的、实验性的纯 Vite 服务端构建器，发布为 [`@nuxt/vite-server`](https://www.npmjs.com/package/@nuxt/vite-server)。
- `packages/webpack`：用于 Nuxt 的 [webpack](https://webpack.js.org) 打包器，发布为 [`@nuxt/webpack-builder`](https://www.npmjs.com/package/@nuxt/webpack-builder)。

[架构概览](https://github.com/nuxt/nuxt/blob/main/ARCHITECTURE.md) 说明了这些包之间如何协作，以及一项更改需要配备哪种层次的测试。

## 环境搭建

要贡献 Nuxt，你需要搭建一个本地环境。

1. [Fork](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/working-with-forks/fork-a-repo) [`nuxt/nuxt`](https://github.com/nuxt/nuxt) 仓库到你自己的 GitHub 账户，然后[克隆](https://docs.github.com/en/repositories/creating-and-managing-repositories/cloning-a-repository)到你的本地设备。
2. 确保使用最新的 [Node.js](https://nodejs.org/en)
3. 启用 [Corepack](https://github.com/nodejs/corepack) 以获得 `pnpm` 和 `yarn`
    ```bash [Terminal]
    corepack enable
    ```
4. 运行 `pnpm install --frozen-lockfile` 用 pnpm 安装依赖：
    ```bash [Terminal]
    pnpm install --frozen-lockfile
    ```
    ::note
    如果你要添加依赖，请使用 `pnpm add`。:br
    `pnpm-lock.yaml` 文件是所有 Nuxt 依赖的权威来源。
    ::
5. 激活被动开发系统
    ```bash [Terminal]
    pnpm dev:prepare
    ```
6. 检出一个你可以工作并提交更改的分支：
    ```bash [Terminal]
    git checkout -b my-new-branch
    ```

然后，在提交 Pull Request 之前，针对 [playground](/docs/community/framework-contribution#playground) 测试你的更改并[测试](/docs/community/framework-contribution#testing)你的更改。

### Playground

在处理 Pull Request 时，你很可能想检查你的更改是否正确。

你可以修改 `playground/` 中的示例应用，并运行：

```bash [Terminal]
pnpm dev
```

:::important
请确保不要将其提交到你的分支，但在 PR 描述中添加一些示例代码可能会有帮助。这可以帮助审查者和其他 Nuxt 用户深入理解你构建的功能。
:::

### 测试

每个新功能和 bug 修复都应有一个对应的测试，并放在能够覆盖它的成本最低的层次上（尽可能写单元测试）。[架构概览中的测试章节](https://github.com/nuxt/nuxt/blob/main/ARCHITECTURE.md#tests)介绍了各个层次以及各自的使用时机。

在创建 PR 或将其标记为准备审查之前，通过运行以下命令确保所有测试通过：

```bash [Terminal]
pnpm test
```

### Lint

你可能已经注意到我们使用 ESLint 来强制代码标准。

在提交更改之前，要验证代码风格是否正确，运行：

```bash [Terminal]
pnpm lint
```

:::note
你可以使用 `pnpm lint --fix` 修复大部分风格更改。:br
如果仍有错误遗留，你必须手动纠正它们。
:::

### 文档

如果你正在添加新功能、重构或以任何其他方式改变 Nuxt 的行为，你可能想要记录这些更改。请将任何文档更改包含在同一 PR 中。你不必在第一次提交时就写好文档（但请在你的 Pull Request 足够成熟时尽快这样做）。

:::important
请确保根据[文档风格指南](/docs/community/contribution#documentation-style-guide)进行更改。
:::

### 最终检查清单

提交 PR 时，有一个你需要填写的简单模板。请在检查清单中勾选所有适当的“答案”。

## 文档指南

如果你发现我们可以改进文档或错误消息的地方，请打开 PR——即使只是修复一个错别字！

:::important
请确保根据[文档风格指南](/docs/community/contribution#documentation-style-guide)进行更改。
:::

### 快速编辑

如果你发现一个错别字或想改写一个句子，可以点击位于右侧边栏 **Community** 板块中的 **Edit this page** 链接。

直接在 GitHub 界面中进行更改并开启一个 Pull Request。

### 较长的编辑

文档内容位于 [nuxt/nuxt](https://github.com/nuxt/nuxt) 仓库的 `docs/` 目录中，使用 markdown 编写。

:::note
要在本地预览文档，请遵循 [nuxt/nuxt.com](https://github.com/nuxt/nuxt.com) 仓库中的步骤。
:::

:::note
我们推荐你为 VS Code 安装 [MDC 扩展](https://marketplace.visualstudio.com/items?itemName=Nuxt.mdc)。
:::

### Lint 文档

文档使用 [MarkdownLint](https://github.com/DavidAnson/markdownlint) 和 [case police](https://github.com/antfu/case-police) 进行 lint，以保持文档的一致性。

```bash [Terminal]
pnpm lint:docs
```

:::note
你也可以运行 `pnpm lint:docs:fix` 来突出并解决任何 lint 问题。
:::

### 开启一个 PR

请确保你的 PR 标题遵循[约定式提交](https://www.conventionalcommits.org)指南。

```bash [Example of PR title]
docs: update the section about the nuxt.config.ts file
```
